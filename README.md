# dx-novels — 『平熱』リーダー

連作小説『平熱 — 株式会社ヤマビコの三年』（全10話）を、PC でもスマホでも読みやすく表示するリーダー。
本文に加えて、あらすじ・世界観・登場人物・相関図を持つ。閲覧専用でサーバーは持たない。

要件・設計判断・進捗は `00_admin/steering/20260910-dx-novels-reader/` に集約している（SSoT）。

公開 URL: https://scioltoharumi.github.io/dx-novels/ （検索エンジンには載せない設定。URL を知る人は誰でも読める）

## ふだんの運用

### 新しい話を足す

```
1. content/ に Markdown を置く
2. meta/novels/chNN.json を書く（あらすじ・登場人物・語録。無くても公開はできる）
3. git add / commit / push
```

退役した原稿は `docs/archive/` に置く（`content/` から外せばサイトから消える）。一つの話を分冊にするときは、ファイル名を `ch06.1_…` `ch06.2_…` のように枝番にする（表示は「第6.1話」、id は `ch06-1`、あらすじは `meta/novels/ch06-1.json`）。

push すると GitHub Actions が 変換 → 検査 → GitHub Pages 反映 まで無人で走る（約1分）。
Actions を手で動かす場面はない。反映されたかは画面いちばん下の「版 <コミット> <時刻>」で分かる。

### 絵を足す

```
1. npm run art        → meta/ART_BRIEF.md に、貼り付けられるプロンプトが36枚ぶん出る
2. 生成した画像を site/img/ の下に、指定の名前で置く
3. git add / commit / push
```

**一部だけ置いてもよい。** 置いていないものは、色と題名・姓の一文字による自動の代替表示のままになる。

| 用途 | パス | 形 |
|---|---|---|
| キービジュアル | `site/img/key.jpg` | 横長 16:9（1920×1080 以上） |
| 表紙 | `site/img/covers/chNN.jpg` | 縦長 2:3（1200×1800 以上） |
| 肖像 | `site/img/characters/<id>.jpg` | 正方形 1:1（1024×1024 以上） |

拡張子は `.svg` `.jpg` `.jpeg` `.png` `.webp` のどれでもよい（同名があれば svg を優先）。人物の `<id>` は `meta/characters.json` の `id`。

### コードで描く線画（`npm run portrait` / `npm run key`）

`scripts/portrait.mjs` が **25人ぶん**の肖像を、`scripts/keyvisual.mjs` が **トップの背景**（四階の小部屋の夜）を SVG の線画として組み立てる。いま site に入っているのはこれ。

- 線は一定幅の `stroke` ではなく、**中心線に沿って太さの変わる塗りのリボン**として作る（`scripts/penlib.mjs` の `ink()`）。これで入りと抜きのある、ペンで引いた線になる
- 髪型・襟・皺・小物は `scripts/portrait-parts.mjs` の型から選ぶ。25人を個別に描くとばらけるので、骨格と部品の組み合わせだけを人物ごとに決める
- 44px でも 128px でも劣化しない。1枚 13〜54KB

| 部品 | 種類 |
|---|---|
| 髪型 | ボブ／散らかった短髪／まとめ髪／きっちり短髪（前髪3種）／七三／撫でつけ／薄い頭頂／パーマ／目にかかる前髪／立てた短髪／量の多いくせ毛／跳ねたくせ毛／肩で切り揃え／一つ結び／ショートボブ |
| 髪の濃さ | 黒（ベタ）／白髪混じり（輪郭＋多めの筋）／白髪（輪郭＋筋） |
| 襟 | カーディガン／丸首（パーカー・T）／ベスト／開襟シャツ／背広（ネクタイ有無）／立ち襟の作業着／襟高のフリース |
| 皺 | なし／薄い／中／濃い（額・ほうれい線・目尻・目の下） |
| 小物 | メモ帳・社員証・串・コーヒー・ペン3本・靴紐・湯呑み・ノート・名刺・電卓・伝票・ケーブル・紙束・ヘッドセット・顎髭・眼鏡4種 |

**ペンで描いた挿絵の水準には届いていない。** 線の質は上げられたが、骨格や髪の形は制御点を数値で置いているだけなので、そこが限界。
生成した絵に差し替えるときは、対応する `.svg` を消して同じ名前の画像を置く（**同名なら svg が勝つ**）。

**肖像は単行本の巻頭にある白黒の登場人物紹介の挿絵**（ペン画・ハッチング・色なし）、**表紙とキービジュアルは色あり**（単行本のカバーにあたる）。

**肖像は正方形で作り、アプリが円形に切り抜いて出す。** 表示は 44px（一覧の小）／48px（相関図）／64px（人物カード）／128px（人物ページの見出し）。
四隅は必ず切り落とされるので、顔を中央に寄せ、頭の上に1割の余白を残し、背景は紙の白のままにする。
**白黒なので色で描き分けられない。** 髪のかたち・眼鏡のかたち・髭・襟のかたち・服の明るさで区別する。25人ぶんの「見分けどころ」の対照表が発注書に入っている。
この指定は `meta/art.json` の `style` と `portraitComposition` に入っていて、発注書に自動で付く。

画面側は、白黒の絵がどの配色でも「紙に刷った挿絵」に見えるようにしてある。肖像の下地は常に紙の色で、暗い配色のときだけわずかに落とす。所属の色は絵の外周の輪として残る。

プロンプトを直すときは `ART_BRIEF.md` ではなく元データを直す。

| 直したいもの | 直す場所 |
|---|---|
| 画風・構図・禁止事項 | `meta/art.json` の `style` / `*Composition` / `avoid` |
| 個人の見た目・年齢・性別 | `meta/art.json` の `portraits.<id>` |
| 人物そのもの（名前・所属・紹介文） | `meta/characters.json` |

原稿で性別が明記されているのは **柳（五十代の男性）・川辺（三十代の女性）・熊谷（六十三歳の男性）の3人だけ**で、
作中に「彼」「彼女」は一度も出てこない。残りは口調と立場から推した提案なので、違えば `gender` を書き換えて `npm run art` をやり直す。

## 原稿の約束ごと

| 項目 | 決まり | 例 |
|---|---|---|
| ファイル名 | 先頭の数字が話の順番。`（ ）` の中身はテーマの既定値 | `ch11_題名（テーマ）_改稿版.md` |
| タイトル | 1行目の `# 見出し`。末尾の `（改稿版）` は表示から外す | `# 三つの売上（改稿版）` → 三つの売上 |
| 章 | `## 見出し` が章。目次はここから作る | `## 第一章　三つの売上` |
| 段落 | 1行＝1段落。段落のあいだは空行 | |
| 場面転換 | `---` | 「＊」として表示 |
| ノートの書き付け | `>` の引用 | 罫線つきの囲みで表示 |
| 図・年表 | ``` のコードブロック | 等幅で表示。横に長ければ横スクロール |
| 用語集 | `\|` の表 | スマホでは1行ずつのカードに積む |

Fable の出力をそのまま置けばよい。番号が重複するとビルドが止まる。

## 構成

```
dx-novels/
├── content/                原稿（Markdown）
├── meta/                   あらすじ・登場人物のデータ。型は meta/SCHEMA.md
│   ├── SCHEMA.md           書き方の定義（人物 id の一覧つき）
│   ├── series.json         世界観・会社・三年の歩み
│   ├── characters.json     人物マスタ（プロフィール・関係・絵の指示）
│   ├── novels/chNN.json    話ごとのあらすじ・章別あらすじ・役割・語録・覚える仕組み
│   ├── art.json            絵の指定（画風・構図・禁止事項・人物ごとの見た目。日英）
│   └── ART_BRIEF.md        絵の発注書（npm run art が生成。手で編集しない）
├── site/
│   ├── index.html          画面の雛形（{{VERSION}} などをビルドで埋める）
│   ├── app.js              画面の切り替え・表示設定・読書位置の記憶・相関図
│   ├── style.css
│   ├── img/                表紙・肖像・キービジュアル（無ければ自動の代替表示）
│   └── dist/               ビルド成果物（gitignore。Actions が作って配信する）
├── scripts/
│   ├── build.mjs           content/ + meta/ → site/dist/
│   ├── check.mjs           検査（章数の一致・未変換記号・人物参照の整合）
│   ├── shot.mjs            見た目と挙動の検証（49項目）＋スクリーンショット
│   ├── portrait.mjs        肖像25人ぶんの線画を組み立てる（部品は portrait-parts.mjs、線は penlib.mjs）
│   ├── keyvisual.mjs       トップの背景（四階の小部屋の夜）を描く
│   ├── art.mjs             絵の発注書の生成
│   └── serve.mjs           ローカル確認用の静的サーバー
└── .github/workflows/deploy.yml   push → build → check → Pages
```

依存ゼロ（`npm install` 不要）。Node 20 以上。

### 画面

| 画面 | URL | 内容 |
|---|---|---|
| トップ | `#/` | キービジュアル、続きから読む、表紙棚（全話・読了率つき） |
| あらすじ・世界観 | `#/about` | 舞台、会社の概要、三年の歩み（年表）、各話のあらすじ、人物一覧への導線 |
| 各話のあらすじ | `#/synopsis/ch01` | キャッチ・あらすじ・覚える仕組み・登場人物・章ごとのあらすじ・結末・語録・キーワード |
| 登場人物 | `#/characters` | 全25人のカード（所属で絞り込み）と相関図 |
| 人物詳細 | `#/characters/rino` | プロフィール・人物像・外見・関係・登場する話ごとの役割・語録 |
| 本文 | `#/ch01` | 本文。ヘッダーは下スクロールで隠れ、上スクロールで戻る |
| 本文の章へ | `#/ch01/s3` | 3番目の見出しへ。目次パネルから飛ぶ |

- **表示設定**（右上「Aa」）: 文字の大きさ 10〜32px・行間 1.2〜2.6・ゴシック／明朝・配色（自動／白／セピア／黒）。変更しても読んでいた段落が画面に残る
- **読書位置**: 話ごとに「いちばん上に見えている段落」を localStorage に記憶し、次に開いたときそこへ戻る。端末ごと（端末をまたいだ同期はしない）
- **ネタバレ**: 章ごとのあらすじと結末は、既定で折りたたみ
- PC: `←` `→` で前後の話、`t` で目次、`Esc` でパネルを閉じる

## ローカルで確認する

```powershell
npm run dev        # 変換 → 検査 → http://127.0.0.1:8000/
npm run shot       # 別ターミナルで。見た目の撮影と挙動 49 項目の検査
```

`file://` では fetch が動かないので、必ずサーバー経由で開く。

`npm run shot` はヘッドレス Edge を DevTools プロトコルで動かす（Playwright 不要）。
スマホ実寸 390px での撮影、読書位置の復元、表示設定、目次、絞り込み、相関図、横はみ出しの有無までを PASS/FAIL で返す。
公開後のサイトに対しても実行できる: `$env:BASE_URL="https://scioltoharumi.github.io/dx-novels"; npm run shot`

## 公開の仕組み

- GitHub Pages（`build_type=workflow`）。`main` への push で `deploy.yml` が走る
- `check.mjs` に落ちると deploy に進まない（壊れた変換を公開しない）
- `app.js` / `style.css` / `data/*.json` は `?v=<コミット>` 付きで読むので、古いキャッシュが残っても最新が届く
- リポジトリは public（GitHub Free の Pages は public が前提）。原稿は自作なので版管理に含める
