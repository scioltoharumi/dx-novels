# dx-novels — DX小説リーダー

Fable に書かせた DX 題材の小説群を、PC でもスマホでも読みやすく表示するリーダー。
文字の大きさ・行間・書体・配色を変えられ、目次や前後の話へすぐ移れる。閲覧専用でサーバーは持たない。

要件・設計判断・進捗は `00_admin/steering/20260910-dx-novels-reader/` に集約している（SSoT）。

公開 URL: https://scioltoharumi.github.io/dx-novels/ （検索エンジンには載せない設定。URL を知る人は誰でも読める）

---

## 新しい話を足す（ふだんの運用はこれだけ）

```
1. content/ に Markdown を置く
2. git add / commit / push
```

push すると GitHub Actions が 変換 → 検査 → GitHub Pages 反映 まで無人で走る（約1分）。
Actions を手で動かす場面はない。反映されたかは画面いちばん下の「版 <コミット> <時刻>」で分かる。

### 原稿の約束ごと

| 項目 | 決まり | 例 |
|---|---|---|
| ファイル名 | 先頭の数字が話の順番。`（ ）` の中身はテーマとして一覧に添える | `ch11_題名（テーマ）_改稿版.md` |
| タイトル | 1行目の `# 見出し`。末尾の `（改稿版）` は表示から外す | `# 三つの売上（改稿版）` → 三つの売上 |
| 章 | `## 見出し` が章。目次はここから作る | `## 第一章　三つの売上` |
| 段落 | 1行＝1段落。段落のあいだは空行 | |
| 場面転換 | `---` | 「＊」として表示 |
| ノートの書き付け | `>` の引用 | 罫線つきの囲みで表示 |
| 図・年表 | ``` のコードブロック | 等幅で表示。横に長ければ横スクロール |
| 用語集 | `\|` の表 | スマホでは1行ずつのカードに積む |

Fable の出力をそのまま置けばよい。番号が重複するとビルドが止まる（同じ番号の話が2つになるため）。

## 構成

```
dx-novels/
├── content/                原稿（Markdown）
├── site/
│   ├── index.html          画面の雛形（{{VERSION}} などをビルドで埋める）
│   ├── app.js              一覧と本文の切り替え・表示設定・読書位置の記憶
│   ├── style.css
│   └── dist/               ビルド成果物（gitignore。Actions が作って配信する）
├── scripts/
│   ├── build.mjs           content/ → site/dist/（Markdown → HTML、一覧 JSON、版の書き出し）
│   ├── check.mjs           変換結果の検査（話数一致・見出し数一致・未変換記号の検出）
│   └── serve.mjs           ローカル確認用の静的サーバー
└── .github/workflows/deploy.yml   push → build → check → Pages
```

依存ゼロ（`npm install` 不要）。Node 20 以上。

### 画面

| 画面 | URL | 内容 |
|---|---|---|
| 一覧 | `#/` | 話の一覧。前回の続きへのカード、話ごとの読了率 |
| 本文 | `#/ch01` | 本文。ヘッダーは下スクロールで隠れ、上スクロールで戻る |
| 本文の章へ | `#/ch01/s3` | 3番目の見出しへ。目次パネルから飛ぶ |

- **表示設定**（右上「Aa」）: 文字の大きさ 14〜32px・行間・ゴシック／明朝・配色（自動／白／セピア／黒）。変更しても読んでいた段落が画面に残る
- **目次**（右上「目次」）: この話の章と、ほかの話の一覧
- **読書位置**: 話ごとに「いちばん上に見えている段落」を localStorage に記憶し、次に開いたときそこへ戻る。端末ごと（端末をまたいだ同期はしない）
- PC: `←` `→` で前後の話、`t` で目次、`Esc` でパネルを閉じる

## ローカルで確認する

```powershell
npm run dev        # 変換 → 検査 → http://127.0.0.1:8000/
```

`file://` では fetch が動かないので、必ずサーバー経由で開く。

## 公開の仕組み

- GitHub Pages（`build_type=workflow`）。`main` への push で `deploy.yml` が走る
- `check.mjs` に落ちると deploy に進まない（壊れた変換を公開しない）
- `app.js` / `style.css` / `data/*.json` は `?v=<コミット>` 付きで読むので、古いキャッシュが残っても最新が届く
- リポジトリは public（GitHub Free の Pages は public が前提）。原稿は自作なので版管理に含める
