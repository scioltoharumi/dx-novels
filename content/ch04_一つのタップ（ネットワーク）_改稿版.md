# 一つのタップ（改稿版）

## 第一章　住所と電話帳

「二月十四日の夜九時、テレビで紹介されるそうです」

　森田がそう言ったのは、年が明けて最初の週だった。

　全国放送の情報番組「日本の名品」が、トレイルシューズIII を十分間取り上げる。番組の放映中と直後に、ヤマビコストアに普段の二十倍のアクセスが来る、と森田は言った。

「二十倍って、根拠は」

　梨乃が聞いた。

「去年、同じ番組で紹介された鎌倉のバッグ屋さんが、放映五分後にサイトが落ちたそうです。そこの社長が業界の集まりで言ってました。普段の二十倍来た、と」

「業界の集まり」

「二次会で」

「二次会の数字ですか」

「二次会の数字です。でも、三回聞いたので、たぶん本当です」

　三回聞いたなら本当、という基準は、梨乃にはなかった。ただ、否定する根拠もなかった。

　小部屋で、赤海はしばらく黙っていた。からあげ棒は、今日は普通のしょうゆ味だった。緊張したときはしょうゆ味らしい、と梨乃は最近気づいていた。

「高梨さんを呼んでくれ」

---

　高梨はヤマビコストアを一人で作り、一人で直し続けているエンジニアだ。三十代前半、フロントエンドが得意で、サーバーの話になると少し表情が硬くなる。小部屋に入るとき、必ず一回、頭を下げる。誰にでもではなく、部屋に対して。

「今のヤマビコストアは、AWS の EC2 という仮想サーバーが一台と、RDS という MySQL が一台。それだけです。一台で二十倍は、たぶん無理です。すみません」

　高梨は正直に言った。まだ何も起きていないのに、謝った。

「二十倍が来たとき、どこで詰まるんですか」

　早瀬が聞いた。高梨は答えに詰まった。

「……えっと、どこかで」

「どこかで」

「すみません」

　赤海が代わりに言った。

「それを知るには、お客さんがスマホでヤマビコストアをタップしてから、注文が保存されるまでに、通信がどこを通るかを、全部知る必要がある。高梨さんも、たぶん半分は知らない」

「半分は知ってます」

「じゃあ、残りの半分をこれから一か月でやる。早瀬さん、ブラウザに store.yamabiko.co.jp と打つと、最初に何が起きる」

「サーバーにアクセスします」

「サーバーは、どこにいる」

　早瀬は黙った。それから、言った。

「……どこかに」

　高梨と早瀬が、同時に「どこか」と言った日だった。

---

「インターネット上の機械には、全部、番号がついてる。IP アドレスという」

　赤海はホワイトボードに書いた。

```
店の住所   店の名前
54.199.12.87   store.yamabiko.co.jp
```

「ヤマビコストアのサーバーの番号は 54.199.12.87 だ。お客さんのスマホは、この番号宛てに通信を送る。だがお客さんは番号を知らない。店の名前しか知らない。だから、名前から番号を引く仕組みがある」

「わかりました！」

　早瀬が言った。

「郵便局ですね！」

「電話帳だ」

「……近くないですか」

「郵便局は配達する。電話帳は番号を引くだけだ。配達はしない」

「近いと思います」

「近くない」

　早瀬は「電話帳」とメモして、その横に小さく「（郵便局ではない）」と書いた。

「DNS。ドメイン・ネーム・システム。store.yamabiko.co.jp という名前を、54.199.12.87 という番号に変換する。ブラウザがまず最初にやるのは、これだ」

　赤海は端末でコマンドを打った。

```
$ dig store.yamabiko.co.jp

;; ANSWER SECTION:
store.yamabiko.co.jp.   300   IN   A   54.199.12.87
```

「答えの行は、こう読む。store.yamabiko.co.jp の A レコード——番号——は 54.199.12.87 だ。真ん中の 300 は、この答えを三百秒、つまり五分間は覚えておいていいという意味。TTL という」

「電話帳は、どこにあるんですか」

「一か所じゃない。階層になってる」

　赤海は木を描いた。木も、あまり上手くなかった。

```
                    ルート（.）
                       │
                      jp
                       │
                     co.jp
                       │
                   yamabiko.co.jp   ← ヤマビコが管理（Route 53）
                       │
              store.yamabiko.co.jp
```

「お客さんのスマホは、まず携帯会社の DNS サーバーに聞く。携帯会社が知らなければ、ルートに聞く。ルートは『jp のことは jp の電話帳に聞け』と言う。jp は『co.jp のことは co.jp に聞け』と言う。co.jp は『yamabiko.co.jp のことは、ヤマビコが Route 53 に置いてる電話帳に聞け』と言う。最後にヤマビコの電話帳が、54.199.12.87 と答える」

「たらい回しですね」

「たらい回しだ。ただし、携帯会社の DNS は、一回聞いたら TTL の間は覚えてる。三百秒だ。だからほとんどの場合、一段階で終わる」

　早瀬がメモした。

「じゃあ、ヤマビコが番号を変えたら、三百秒は古い番号が使われる」

「そうだ。それが今回、最初の落とし穴だ」

---

　落とし穴は、その週の木曜に現実になった。

　丸嘉の開発者から、メールが来た。「api.yamabiko.co.jp に接続できません。名前解決はできますが、接続先が違うようです」。

　高梨が調べた。

　丸嘉向けの在庫 API は、先月、新しいサーバーに置いた。そのとき高梨は Route 53 に api.yamabiko.co.jp のレコードを追加した。ただし、コピー元の設定を間違えて、番号は古いテスト用サーバーのものだった。気づいて水曜の夜に直した。

「直したのに、木曜の朝もつながらない」

「TTL は」

　赤海が聞いた。高梨が画面を見せた。

```
api.yamabiko.co.jp.   86400   IN   A   54.199.12.87
```

「八万六千四百秒」

「一日だ」

「……すみません」

「謝る前に、計算しろ。丸嘉の DNS サーバーは、水曜の昼に古い番号を引いて、一日それを覚えてる。高梨さんが水曜の夜に直しても、丸嘉側は木曜の昼まで古い番号を使い続ける。誰も間違ってない。電話帳が、そういう仕組みだ」

「どうすれば」

「今回は待つ。木曜の昼を過ぎれば直る。次からは、番号を変える予定があるレコードは、変える一週間前に TTL を六十秒に下げておく。変えたら、落ち着いてから戻す。二月十四日に向けて、store のレコードも同じことをする」

　高梨はうなずいた。少し悔しそうだった。

　その日の昼、廊下で三上が高梨に缶コーヒーを渡していた。

「丸嘉の件、直ったんだろ」

「まだです。昼過ぎに直ります」

「じゃあ昼過ぎに直るのはお前のおかげだ」

「電話帳のおかげです」

「電話帳？」

「……はい」

　三上は「わかった！」と言って、缶コーヒーを置いていった。高梨は、何もしていないのに缶コーヒーをもらう人生を、少し受け入れ始めていた。

　梨乃はノートに書いた。

> IP アドレス＝機械の番号。DNS＝名前から番号を引く電話帳（郵便局ではない）。階層になっている。
> TTL＝答えを覚えていていい時間。変更は TTL の間、届かない。変える前に TTL を短くする。
> （二次会の数字は三回聞いたら本当）

---

## 第二章　ドアと往復

「番号がわかったら、次は何をするんですか」

　翌週、早瀬が聞いた。赤海は端末で、別のコマンドを打った。

```
$ curl -v https://store.yamabiko.co.jp/
*   Trying 54.199.12.87:443...
* Connected to store.yamabiko.co.jp (54.199.12.87) port 443
```

「番号の後ろに、コロンと 443 がある。ポートという。機械には番号が一つだが、ドアは六万五千ある。ドアごとに、中で待ってる担当が違う」

```
ポート   待っている担当
   22    SSH（管理者がサーバーに入る）
   80    HTTP（暗号なしのウェブ）
  443    HTTPS（暗号ありのウェブ）
 3306    MySQL
```

「六万五千のドア」

　早瀬が呟いた。

「それ、部長のテントで言うと何張分ですか」

「テントで数えるな」

「すみません」

「ブラウザは、ウェブなら 443 番のドアを叩く。MySQL に直接話したければ 3306 番。ヤマビコストアのサーバーは、443 番のドアの内側で、ウェブサーバーが待ってる」

「3306 番のドアも、インターネットから叩けるんですか」

「叩けたら大事故だ。それは第四章でやる」

「第四章」

「……四つ目の話だ」

　高梨が、何かを言いかけて、やめた。赤海はそれに気づいたが、何も言わなかった。

　赤海は curl の出力を、さらに下にスクロールした。

```
> GET / HTTP/1.1
> Host: store.yamabiko.co.jp
> User-Agent: curl/8.4.0
> Accept: */*
>
< HTTP/1.1 200 OK
< Content-Type: text/html; charset=utf-8
< Content-Length: 48213
< Set-Cookie: session=a8f3c2e1...; HttpOnly; Secure
<
< <!DOCTYPE html>
< <html lang="ja">
< <head><title>ヤマビコストア</title>
```

「大なり記号の行が、ブラウザからサーバーへの手紙。『GET / をくれ』『宛先は store.yamabiko.co.jp』『私は curl だ』。小なり記号の行が、サーバーからの返事。『200、OK』『中身は HTML』『長さは四万八千バイト』『Cookie を持っていけ』。そして本文」

「Set-Cookie は、前作で出た」

「セッション番号だ。ここで発行されてる。ブラウザは次の通信から、この番号を手紙に添えて送る」

「これが一往復」

「一往復だ。ヤマビコストアのトップページを開くと、この往復が、実は一回では済まない。HTML の中に、画像が四十枚、CSS が三つ、JavaScript が八つ書いてある。ブラウザはそれを見て、五十一回、追加で往復する」

　早瀬は驚いた。

「五十一回」

「トップページ一枚で五十一往復。二十倍のお客さんが来れば、千回分の往復が一斉に来る。ただし、この五十一回は全部同じ重さじゃない。画像は一回作ったら変わらない。HTML は、お客さんごとに『こんにちは佐藤花子さん』と中身が変わる。この違いが、五つ目の話で効いてくる」

「五つ目」

「章と言わないようにしてる」

---

「もう一つ。往復の前に、握手がある」

　赤海は curl の出力の、一番上に戻った。

```
*   Trying 54.199.12.87:443...
* Connected to store.yamabiko.co.jp (54.199.12.87) port 443
```

「Trying から Connected までの間に、ブラウザとサーバーは三回、短い信号を交わしてる。『話していいか』『いいぞ、そっちは』『こっちもいい』。これを三ウェイ・ハンドシェイクという。TCP という約束事の一部だ」

「三回の握手」

「わかりました！　六回の手の動きですね！」

「早瀬さん」

「はい」

「もう数えるな」

「はい」

「なぜ三回も、と聞け」

「なぜ三回も」

「インターネットは、途中で信号が消えることがある。三回の握手で、『お互いに、相手の信号が届いてる』ことを確かめてから、本題に入る。届かなかった信号を、送り直す仕組みも TCP の中にある。だからブラウザは、途中で信号が消えても、壊れた HTML を受け取らない」

「三回の握手に、時間はかかりますか」

「かかる。東京のスマホから東京のサーバーなら、片道二ミリ秒、三回で六ミリ秒。だが東京のスマホからアメリカのバージニアにあるサーバーなら、片道八十ミリ秒、三回で二百四十ミリ秒。握手だけで、目に見えるくらい遅くなる」

「ヤマビコストアは」

「東京にある。AWS の東京リージョン。ただし、二月十四日は、握手の回数そのものが二十倍になる」

　赤海は端末に、もう一つ数字を出した。

```
$ curl -o /dev/null -s -w 'dns:%{time_namelookup} tcp:%{time_connect} tls:%{time_appconnect} total:%{time_total}\n' https://store.yamabiko.co.jp/
dns:0.012 tcp:0.015 tls:0.048 total:0.212
```

「電話帳を引くのに十二ミリ秒。握手が終わるのが十五ミリ秒。暗号の準備が終わるのが四十八ミリ秒。HTML が届き切るのが二百十二ミリ秒。この内訳を、二月十四日の夜、二十倍の負荷で、それぞれどう変わるかを見る」

「tls というのは」

「次の話だ。それと、丸嘉の API のテストが今日の午後にある。高梨さんを手伝ってくれ」

---

　午後、丸嘉の開発者とのオンライン会議で、高梨は在庫 API のテストをした。丸嘉側が、先月の入場券を使って、在庫を読む。

```
GET https://api.yamabiko.co.jp/v1/inventory?sku=A3610-BK-26
Authorization: Bearer eyJhbGciOi...

HTTP/1.1 200 OK
{ "sku": "A3610-BK-26", "available": 42 }
```

「つながりました」

　丸嘉の開発者が言った。高梨が、画面の外で小さくガッツポーズをしたのを、早瀬は見た。

　それから、丸嘉の開発者が聞いた。

「ちなみに、御社の API サーバーの IP は固定ですか。弊社のファイアウォールで、接続先を絞りたいので」

　高梨は赤海を見た。赤海が答えた。

「固定にします。二月中に、API の前に固定の番号を持つ入口を置きます」

　会議が終わってから、早瀬が聞いた。

「入場券があるのに、番号でも絞るんですか」

「二重にする。入場券が盗まれても、丸嘉の番号からしか受け付けなければ、盗んだ人は使えない。逆に、番号を偽装されても、入場券がなければ入れない。ゼロトラストの『毎回、複数の条件で確かめる』は、ネットワークの層にもある」

「ライブの入場券と、本人確認の身分証」

「森田さんの例えが移ってるな」

「移りました」

　その日の夕方、三上が高梨に缶コーヒーを渡していた。

「丸嘉の API、つながったんだろ」

「つながりました」

「よくやった」

「今日は、本当に僕がやりました」

「知ってる」

　三上は、知っていた。高梨は少し嬉しかった。

　梨乃はノートに書いた。

> ポート＝機械のドア。443 がウェブ、3306 が MySQL。テントでは数えない。
> HTTP＝手紙の往復。トップページ一枚で五十一往復。画像は不変、HTML は人ごとに変わる。
> TCP＝三回の握手と、消えた信号の送り直し。距離が遠いと握手が遅い。
> 番号での制限と入場券は二重にする。
> （今日は本当に高梨さんがやった）

---

## 第三章　封筒

　一月の最後の日曜日、午前十時、梨乃のスマホが鳴った。

　森田だった。

「ヤマビコストアが、開けません。『この接続ではプライバシーが保護されません』って出ます」

　梨乃は自分のスマホで開いた。同じ画面が出た。赤い警告。「証明書の有効期限が切れています」。

　赤海に電話した。赤海は三分で原因を言い当てた。日曜の午前十時に、三分で出た。たぶん、小部屋にいた。

「証明書が切れた。高梨さんが去年の一月に手で入れたやつだ。一年で切れる」

　高梨は日曜の昼に会社に来て、新しい証明書を入れ直した。サイトは午後一時に復旧した。三時間、ヤマビコストアは誰にも開けなかった。日曜の午前中で、まだ良かった。二月十四日の夜だったら、と全員が思った。

「去年入れたとき、期限をカレンダーに書きました」

　高梨は、小部屋で言った。

「どこのカレンダーに」

「去年のカレンダーに」

「……去年の」

「一月に入れたので、去年のカレンダーの、一月のページに、『来年の一月に更新』と書きました。去年のカレンダーは、十二月に捨てました」

　小部屋が静かになった。串の缶だけが鳴った。

「高梨さん」

「はい」

「それは、誰も悪くない」

「……そうですか？」

「悪くないが、もう二度とカレンダーに書くな」

---

　月曜、小部屋にはいつもの顔ぶれと、高梨がいた。岡崎も来ていた。証明書と聞いて、来た。

「先週、tls という言葉が出た。今日はそれをやる。まず、なぜ暗号が要るか」

　赤海はホワイトボードに、手紙の絵を描いた。封筒の絵は、なぜか比較的上手かった。

「お客さんのスマホからヤマビコのサーバーまで、通信は十か所くらいの機械を経由する。携帯会社の基地局、携帯会社の中継、インターネットの交換点、AWS の入口。その全部で、通信の中身は読める。封をしてない葉書と同じだ。クレジットカード番号を葉書で送る人はいない」

「三上部長は」

「……たぶん、送らない」

「だから封筒に入れる」

「TLS が封筒だ。HTTPS の S は、TLS で封をした HTTP という意味。封筒に入れると、途中の機械は『誰から誰へ』はわかるが、中身は読めない」

「暗号の鍵は、どうやってお客さんとサーバーで共有するんですか。鍵を送ったら、途中で読まれますよね」

　早瀬の質問に、赤海は少し嬉しそうにした。からあげ棒が、早瀬のほうに五度ほど傾いた。

「そこが TLS の一番きれいなところだ。二人が、盗み聞きされてる前提で、盗み聞きしてる人にはわからない鍵を、その場で作る。鍵交換という。数学の話なので中身は省くが、『途中を全部見られてても、鍵は漏れない』ということだけ覚えろ。先週の curl の、tcp が十五ミリ秒で tls が四十八ミリ秒だった。三十三ミリ秒が、この鍵作りだ」

「じゃあ証明書は、何のためにあるんですか。鍵はその場で作れるなら」

「その場で作る相手が、本物のヤマビコかどうかを確かめるためだ」

　赤海はもう一枚、絵を描いた。お客さんのスマホと、ヤマビコのサーバーの間に、偽物のサーバーが割り込んでいる。偽物の絵には、なぜか髭が描いてあった。

「偽物が『私がヤマビコです』と言って、お客さんと鍵を作れば、お客さんは偽物に封筒を渡す。偽物は開けて読んで、本物に転送する。お客さんは気づかない。これを中間者攻撃という。防ぐには、鍵を作る相手が本物だと、誰かが保証する必要がある」

「それが証明書」

「証明書には、こう書いてある」

```
Subject:     CN=store.yamabiko.co.jp
Issuer:      CN=Amazon RSA 2048 M02
Not Before:  2026-01-27
Not After:   2027-02-26
Public Key:  (ヤマビコの公開鍵)
Signature:   (Issuer の秘密鍵による署名)
```

「『この公開鍵は、store.yamabiko.co.jp のものだ』と書いてあり、Issuer——認証局という——が署名してる。お客さんのスマホには、信頼できる認証局の一覧があらかじめ入ってる。スマホは、証明書の署名を認証局の公開鍵で確かめ、本物だと判断して、その公開鍵の持ち主と鍵交換をする。偽物は、認証局の署名を持ってないから、はじかれる」

「印鑑ですね」

　岡崎が言った。

「印鑑です。前回の、Entra ID の印鑑と同じ話です。誰かが署名し、誰かが検証する。SAML では Entra ID が署名した。TLS では認証局が署名する」

「認証局は、役所ですか」

「役所に近い。ただし民間だ」

「民間の役所」

「……そういうことになる」

「言うな」

「はい」

　早瀬が気を取り直して言った。

「54 で始まるのは、インターネットから見える番号、パブリック IP だ。10 で始まるのは、敷地の中だけで通じる番号、プライベート IP。敷地の中の機械は全部、10 で始まる番号を持ってる。インターネットから見える番号は、そのうちの一部にだけ、追加で貼ってある」


「敷地は、区画に分かれてる。サブネットという。public という区画には、インターネットに面した道がある。private という区画には、その道がない。ウェブサーバーは public にいて、お客さんから見える。MySQL は private にいて、インターネットからは、どうやっても届かない」

「一つ目？」

「二つ目がある」

　赤海は、もう一つの設定画面を開いた。

```
セキュリティグループ: sg-web

セキュリティグループ: sg-db
  インバウンド:  3306 from sg-web       （sg-web を付けた機械からだけ、3306 番）
```

「セキュリティグループは、機械一台ごとの門番だ。sg-web という門番は、『443 番のドアは誰にでも開ける。22 番のドアは、赤海の自宅の番号からしか開けない。それ以外のドアは、全部閉めておく』と決めてる。sg-db という門番は、『3306 番のドアは、sg-web の札を付けた機械からしか開けない』」

　高梨が、少し言いにくそうに言った。

## 第六章　壁のない社内

「もう一つ、宿題が残ってる」

　二月十二日、放映の二日前、赤海は小部屋に岡崎と倉庫の佐藤を呼んだ。

　赤海は、神田のオフィスと埼玉の倉庫の絵を描いた。

```
神田オフィス 192.168.1.0/24
  ┌───────────────────────────────────┐
  │ 社員PC × 40  来客用Wi-Fi  複合機   │
  │ ファイルサーバー  会計システム      │
  └────────────┬──────────────────────┘
               │ 拠点間VPN（固定回線）
  ┌────────────┴──────────────────────┐
  │ 倉庫PC × 5  ハンディ端末 × 12       │
  │ 倉庫システム（サーバー）  ラベルプリンタ │
  └───────────────────────────────────┘
埼玉倉庫 192.168.2.0/24
```

「秋の事故を覚えてるか。佐藤さんの共用パソコンが乗っ取られ、そこから倉庫システムに入られた」

「付箋の」

「付箋の。VPN を廃止したのは、社外からの道を絞るためだった。だが、あの事故の本質は、もう一つある。乗っ取られた共用パソコンから、倉庫システムに『届いた』ことだ」

「同じネットワークだから」

「そうだ。倉庫の五台のパソコンと、十二台のハンディ端末と、倉庫システムのサーバーと、ラベルプリンタが、全部同じ 192.168.2 の中にいる。どれか一台が乗っ取られれば、残り全部に届く。さらに、拠点間 VPN で神田とつながってるから、神田のファイルサーバーにも、会計システムにも届く」

「AWS の敷地は、public と private に分けてましたよね。社内は分けてないんですか」

　早瀬が聞いた。

「分けてない。平らだ。これを、分ける」

　赤海は絵を描き直した。

```
神田オフィス
  VLAN 10  社員PC（Intune 管理端末のみ）      192.168.10.0/24
  VLAN 20  来客Wi-Fi（インターネットだけ）    192.168.20.0/24
  VLAN 30  複合機・IoT                        192.168.30.0/24
  VLAN 40  サーバー（会計・ファイル）          192.168.40.0/24

埼玉倉庫
  VLAN 50  倉庫PC                             192.168.50.0/24
  VLAN 60  ハンディ端末                        192.168.60.0/24
  VLAN 70  倉庫システム（サーバー）            192.168.70.0/24
  VLAN 80  ラベルプリンタ・IoT                 192.168.80.0/24
```

「VLAN という。物理的には同じスイッチにつながってても、論理的に別々の区画にする。AWS のサブネットと同じ考え方だ。そして区画の間に、門番を置く」

```
許す通信
  VLAN 50 倉庫PC      → VLAN 70 倉庫システム   443 のみ（Cloudflare Access 経由）
  VLAN 60 ハンディ    → VLAN 70 倉庫システム   443 のみ
  VLAN 10 社員PC      → VLAN 40 サーバー       443, 445
  VLAN 20 来客Wi-Fi   → インターネットのみ。社内には一切届かない

許さない通信
  VLAN 50 倉庫PC      → VLAN 10 社員PC         （倉庫から神田の PC には届かない）
  VLAN 80 プリンタ    → どこにも               （プリンタから始まる通信は不要）
  VLAN 30 複合機      → インターネット         （複合機がクラウドに勝手に出ない）
```

「秋の事故を、この設計に通す。共用パソコンは VLAN 50 にいる。乗っ取られた。倉庫システムには 443 番で届くが、その前に Cloudflare Access の門番がいて、Entra ID の認証と MFA と Intune の証明書を求める。乗っ取ったパソコンは佐藤さんの証明書を持ってるから、そこは通るかもしれない。だが、admin という全能アカウントはもうない。佐藤さんの権限は『出荷指示の確認』だけだ。配送先の一括変更はできない」

「神田のファイルサーバーには」

「届かない。VLAN 50 から VLAN 40 への道はない。乗っ取られた被害は、VLAN 50 の中で止まる」

　佐藤が聞いた。

「ハンディ端末を、わざわざ別の区画にするのは」

「ハンディ端末は、Android の古い版で動いてて、更新が止まってる。乗っ取られやすい。乗っ取られても、倉庫システムの 443 番にしか届かないようにしておく。弱いものを、別の部屋に入れる」

「弱いものを、別の部屋に」

　佐藤は少し考えて、言った。

「三上部長も、別の部屋ですか」

　小部屋が静かになった。

「……部長は、VLAN 10 だ」

「社員 PC と同じ」

「Intune が入ってる。部長のパソコンは、会社が管理してる。部長本人は管理できてないが、パソコンは管理できてる」

「パソコンだけ」

「パソコンだけだ」

　岡崎がチェックシートを開いた。

「Q31 の、社外からのアクセス制御は、秋に『はい』にしました。この社内の分割は、Q33 の『ネットワークセグメンテーション』ですね」

「そうだ。残り八項目のうちの一つ」

「あと七つ」

「あと七つ」

　岡崎は「あと7」と書いた。「残り3つ」の隣に。

---

「もう一つ。丸嘉の API に、固定の番号を約束した」

　赤海は AWS の絵に戻った。

「API サーバーは、ウェブサーバーと同じ ALB の後ろに置いた。だが ALB の番号は、AWS の都合で変わることがある。丸嘉は、ヤマビコの番号をファイアウォールに登録したい。番号が変わるたびに丸嘉に連絡するのは、現実的じゃない」

「どうするんですか」

「ALB の前に、もう一つ、固定の番号を持つ入口を置く。Global Accelerator というサービスがあり、二つの固定 IP をくれる。丸嘉にはその二つを伝える。逆に、ヤマビコの WAF には、丸嘉の番号からしか /v1/inventory を受け付けない、という規則を足す」

```
丸嘉 203.0.113.0/24 ──▶ 固定IP 75.2.x.x ──▶ WAF（丸嘉の番号のみ許可）──▶ ALB ──▶ API サーバー
                         + OAuth 入場券
```

「番号と入場券の二重。二つ目の話で言った通りだ」

　早瀬が、ふと聞いた。

「Snowflake も Power BI も、社外にありますよね。あれは、どう守ってるんですか。VLAN の外です」

「Snowflake には、『ヤマビコのオフィスと、AWS の NAT の番号からしか受け付けない』という設定がある。ネットワークポリシーという。Power BI は Entra ID の条件付きアクセスで、Intune の端末からしか開けない。社外のサービスも、番号と本人と端末で絞る。壁がない代わりに、一つ一つの前に門番を立てる。秋にやったことと同じだ」

「三上部長が、六十回押すのも」

「Intune の端末から、MFA を通って、六十回押してる。六十回、門番が確かめてる」

「門番、大変ですね」

「機械だ」

　梨乃はノートに書いた。

> 社内も、平らにしない。VLAN で区画に分け、区画間に門番を置く。AWS のサブネットと同じ。
> 弱いもの（古い端末、プリンタ、来客）は、別の部屋に入れる。
> 乗っ取られたとき、被害がその部屋で止まるように。
> 社外サービスも、番号・本人・端末で絞る。
> （部長はパソコンだけ管理されている。残り7）

## 終章　一つのタップ

　二月十四日、夜九時七分。

　番組の中で、トレイルシューズIII が映った。司会者が「軽い」と言い、ゲストが「これで高尾山に登りたい」と言った。画面の下に、ヤマビコストアの名前が出た。

　杉並区の佐藤花子は、ソファでスマホを持ち、「ヤマビコ」と検索して、店名をタップした。

---

　小部屋では、赤海、高梨、梨乃、早瀬、森田が、三枚のモニターを見ていた。一枚は CloudFront のグラフ、一枚は ALB のグラフ、一枚は RDS のグラフ。

　森田は充電器を三本持ってきていた。三本とも、正しいものだった。

　三上もいた。呼んでいないのに来た。スマホを握っていた。

「今、買っていいか」

「だめです」

「なんでだ」

「部長のカートが、二十倍のお客さんと同じ行列に並ぶからです」

「俺はお客さんだ」

「お客さんですが、今日は待ってください」

　三上は不満そうに、スマホをポケットにしまった。三十秒後に、また出した。

　九時七分、CloudFront の線が、垂直に立ち上がった。

「来た」

　高梨が言った。

「普段の、二十二倍です」

「二次会の数字、当たってた」

　森田が言った。少し誇らしげだった。

　九時八分、ALB の線が立ち上がった。CloudFront の線の、二十分の一の高さだった。三台のウェブサーバーの CPU は、四十パーセント。RDS は、十五パーセント。

　高梨が、モニターに向かって小さく「#2、頑張れ」と言った。誰も聞いていないふりをした。

　九時十分、注文が入り始めた。一分間に八十件。普段は一時間に八十件だ。

「今、買っていいか」

「だめです」

　九時十五分、WAF が、一つの番号から一秒に二百回叩いてくる通信を捨て始めた。ログに、その番号がロシアであることが記録された。

「ロシアからテントを買いに来たのか」

「買いに来てません。叩きに来てます」

「叩く？」

「壊しに来てます」

「ロシアの人も、テントは好きだろう」

「好きかもしれませんが、今日のは違います」

　九時三十分、番組が終わった。線はゆっくりと下がっていった。

　九時三十一分、梨乃のスマホが鳴った。社長だった。

「体温は」

「平熱です」

「そうか」

　電話は三秒で切れた。梨乃は「平熱」とノートに書いた。一年半前の階段の日から、この言葉は、ヤマビコで通じる言葉になっていた。

　九時四十分、赤海が言った。

「部長、買っていいです」

「おお！」

　三上はスマホを出して、トレイルシューズIII を買った。二十六と二十七を、一足ずつ。

「テントじゃないんですか」

「今日はテレビに出た靴だ。記念だ」

　注文 id=10598 と 10599 が、MySQL に入った。

　その夜、ヤマビコストアは一度も止まらなかった。

---

　翌朝、赤海は早瀬に、いつもの問いを投げた。

「昨日の夜、佐藤花子さんがスマホで『購入する』を押したとき、何が起きたか。最初から最後まで」

　早瀬は、壁の図の前に立った。この小部屋の壁には、もう四枚の図が貼ってあった。付箋は、十枚を超えていた。

「花子さんのスマホは、まず store.yamabiko.co.jp の番号を、携帯会社の電話帳に聞きました。郵便局ではなく、電話帳です。先週、高梨さんが TTL を六十秒にしていたので、電話帳は新しい番号を持っていました。CloudFront の番号です」

「スマホは、その番号の 443 番のドアを叩きました。三回の握手をして、封筒の鍵を作りました。証明書は ACM のもので、期限は来年です。人は触っていません。カレンダーにも書いていません」

「『購入する』の通信は、封筒に入って CloudFront の東京拠点に届きました。これは画像ではなく、花子さんだけの通信なので、CloudFront は控えを持っていません。そのまま WAF に渡しました。WAF は、SQL の命令も、異常な回数もないので、通しました。ロシアではなく杉並でした。ALB は三台のうち #2 に渡しました。高梨さんが頑張れと言った台です」

「#2 は、封筒を開けて、Cookie のセッション番号を読みました。セッションは ElastiCache にあるので、#2 は花子さんが #1 で入れたカートを、ちゃんと見つけました。#2 は 10.0.11.5 の 3306 番に、注文の一行を書きました。sg-db の門番は、#2 が sg-web の札を持っているので、通しました」

「MySQL に、注文 id=10597 が一行、入りました。#2 は『注文完了』の HTML を封筒に入れて、ALB、CloudFront を通って、花子さんのスマホに返しました。合計で、三百ミリ秒くらいです」

　早瀬は、一枚目の図——一年半前に梨乃が貼った、最初の図——を指した。

「そして、一時間後の十時に、その一行はレイクにコピーされました。今朝五時に、dbt が fact_orders に並べました。花子さんは C-000771 で、商品は P-00512 で、八時に三上部長が Power BI を開いたとき、昨日の売上の棒グラフの一番上に、一ミリの高さで乗っていました」

「その隣に」

「部長の二足も、乗っていました。二ミリです」

　赤海は椅子を回した。

　それから、からあげ棒を、高梨に差し出した。

　高梨は、少し驚いて、それから受け取った。

「僕、何もしてないです」

「昨日はした」

「……はい」

　高梨は食べた。三上が「俺には？」と言い、赤海は「部長は靴を買った」と答えた。三上は納得しなかったが、缶コーヒーを高梨に渡した。理由は「靴が届いたから」だった。まだ届いていなかった。

---

　梨乃はその夜、ノートの最後のページに書いた。

> IP＝番号。DNS＝電話帳（郵便局ではない）。TTL＝覚えていていい時間。変える前に短くする。
> ポート＝ドア。HTTP＝手紙の往復。TCP＝三回の握手と送り直し。
> TLS＝封筒。鍵はその場で作る。証明書＝本物の保証。期限は人が管理しない。カレンダーは捨てられる。
> VPC＝敷地。サブネット＝区画。public は道あり、private は道なし。
> セキュリティグループ＝機械ごとの門番。道と門番で二重。NAT＝出るだけの道。
> CDN＝変わらないものを近くで返す。ALB＝一つの番号の後ろに複数台。道を広げる（社長）。
> 複数台にするなら、セッションを外に出す。WAF＝中身を読む門番。
> 社内も平らにしない。VLAN で区画に分け、弱いものは別の部屋へ。部長はパソコンだけ。
>
> 一つのタップは、十の層を通る。どの層で詰まるかは、層ごとに測らないとわからない。
> （二次会の数字は当たった。ロシアはテントを買いに来たのではない。高梨さんは昨日、した）

## 付録　登場した仕組みと用語

| 物語での呼び方 | 正式名称 | 製品例 | 役割 |
|---|---|---|---|
| 番号 | IP アドレス | — | 機械の宛先。パブリック（外から見える）とプライベート（敷地内） |
| 電話帳（郵便局ではない） | DNS | Route 53, Cloudflare DNS | 名前から番号を引く。階層構造。たらい回し |
| 覚えていていい時間 | TTL | — | 変更前に短くしておく。丸嘉は一日待った |
| ドア | ポート | 443, 22, 3306 | 一つの番号に六万五千のドア。テントでは数えない |
| 手紙の往復 | HTTP | — | GET/POST とステータス。ページ一枚で数十往復 |
| 三回の握手 | TCP 3-way handshake | — | 届いていることの確認と送り直し。六回とは数えない |
| 封筒 | TLS / HTTPS | — | 途中の機械に中身を読ませない。鍵はその場で作る |
| 本物の保証 | 証明書 / 認証局（民間の役所） | ACM, Let's Encrypt | 公開鍵の持ち主を認証局が署名。期限は自動更新。去年のカレンダーには書かない |
| 敷地 | VPC | AWS VPC | クラウド内の私有ネットワーク。六万五千は偶然 |
| 区画 | サブネット | public / private | 道あり／道なし。DB は private |
| 機械ごとの門番 | セキュリティグループ | — | ドア番号と相手で開閉。道との二重。3306 は来た週に直した |
| 出るだけの道 | NAT ゲートウェイ | — | private から外へ。家庭の Wi-Fi ルーターと同じ。テントは繋がっていない |
| 近くで返す | CDN | CloudFront, Cloudflare | 静的ファイルを拠点に控えを置く。TTL あり |
| 道を広げる | ロードバランサー | ALB | 振り分けと生存確認。証明書の置き場。社長が当てた回 |
| セッションの外出し | 外部セッションストア | ElastiCache (Redis) | 複数台でカートが消えないように。部長の三つも |
| 中身を読む門番 | WAF | AWS WAF, Cloudflare WAF | SQL 注入・レート制限。ロシアはテントを買いに来たのではない |
| 固定の入口 | 固定 IP / Anycast | Global Accelerator | 取引先が番号でファイアウォールを絞れるように |
| 社内の区画 | VLAN / セグメンテーション | — | 平らにしない。区画間に門番。弱いものは別の部屋（部長はパソコンだけ） |
| 社外サービスの絞り込み | ネットワークポリシー / 条件付きアクセス | Snowflake network policy, Entra 条件付きアクセス | 番号・本人・端末で絞る。六十回でも |
