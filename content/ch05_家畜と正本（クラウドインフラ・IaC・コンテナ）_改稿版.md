# 家畜と正本（改稿版）

## 第一章　五十倍

「もう一度テレビが来たら、大丈夫か」

　三月の経営会議で、大河内はそう聞いた。

　二月十四日の夜、ヤマビコストアは二十二倍のアクセスを受けて止まらなかった。売上は一晩で通常の三週間分だった。社長はそれを喜んでから、次の質問をした。

「二十二倍で、サーバーは何パーセントだった」

「三台で、四十パーセントでした」

　梨乃が答えた。

「五十倍が来たら」

「三台では足りません。台数を増やす必要があります」

「増やすのに、何日かかる」

　梨乃は赤海を見た。赤海が答えた。

「今の作り方だと、一台あたり半日です。高梨さんが手で作るので」

「テレビは、放映の五分後に来るんだろう」

「はい。だから、人が増やすのでは間に合いません。機械が自分で増える仕組みにします」

「サーバーってのはな」

　来た。梨乃はペンを止めた。

「牛みたいなもんだ。牛は……牛乳が出る」

「はい」

「増やしたきゃ、牛を増やせばいい」

　社長はそう言って、次の議題に移った。赤海が、珍しく、会議の席で小さく笑った。梨乃はそれを見逃さなかった。

---

　小部屋に、高梨と、三月に入社したばかりの桐山がいた。

　桐山は二十四歳、前職は受託開発の会社で、ヤマビコが初めて雇った二人目のエンジニアだ。初日に小部屋に来たとき、自分でコンビニのからあげ棒を買ってきて、赤海の隣で食べた。

「……それは違う」

「え、何がですか」

「からあげ棒は、俺が渡すものだ」

「あ、すみません、噂で聞いて、これが正装なのかと」

「正装ではない」

　桐山は、その日以来、からあげ棒を持ってこなかった。代わりに、ノートを持ってきた。表紙に「赤海語録」と書いてあった。赤海はそれを見て、何も言わなかった。

「二月に、ウェブサーバーを三台にした。高梨さん、あの三台は、どうやって作った」

　赤海が聞いた。高梨は正直に答えた。

「一台目を作って、AWS の画面で『イメージを作成』を押して、二台目と三台目はそのイメージから起動しました。そのあと、三台それぞれに入って、設定ファイルを直しました」

「三台の中身は、今、同じか」

　高梨は少し考えた。

「たぶん、同じです。#2 だけ、二月十三日にログの設定を変えたのを、#1 と #3 に反映したかどうか」

「#2 だけ」

「#2 は、僕が一番、話しかけてるので」

　桐山が「話しかける？」と言い、高梨が「頑張れって」と言い、桐山は「赤海語録」に書かなかった。高梨語録だった。

「それが問題だ」

　赤海はホワイトボードに書いた。

```
ペット   ＝ 名前をつけて、手で世話をして、病気になったら看病するサーバー
家畜     ＝ 番号で管理して、同じものを何頭でも作り、病気になったら入れ替えるサーバー
```

「牛だ」

　梨乃が言った。

「牛だ」

　赤海が認めた。社長は今回も、当たった半分だった。

「今のヤマビコの三台は、ペットだ。#1、#2、#3 という名前があり、高梨さんが一台ずつ中に入って世話をしてる。ペットは増やせない。五十倍が来て三十台必要になったとき、三十台の世話はできない」

「三十台に、頑張れって言えない」

　高梨が呟いた。

「言えない。家畜にする。同じ中身のサーバーを、機械が何台でも自動で作れるようにする。そのためには、一台のサーバーの中に『そこにしかないもの』があってはいけない」

　桐山が聞いた。

「そこにしかないもの、というのは」

「二月に、セッションを ElastiCache に外出しした。あれが一つ目だ。セッションがサーバーの中にあると、そのサーバーを止められない。他には、アップロードされた商品画像。ログ。設定ファイルの手直し。全部、サーバーの外に出す。画像は S3 へ。ログは CloudWatch へ。設定は、起動時に外から読み込む」

「そうすると、サーバーの中には何が残るんですか」

「プログラムと、それを動かすソフトだけ。それも、起動時に外から持ってくる。サーバーは、起動したときに『自分は何者か』を外から教わり、仕事をして、止められたら何も残さず消える。そういうサーバーは、何台でも作れるし、何台でも消せる」

「消える」

　高梨が、小さな声で言った。

「#2 も、消えるんですか」

「消える。#2 も、#1 も、#3 も。番号のない牛になる」

「……」

「高梨さん」

「はい」

「#2 は、二月十四日に、四十パーセントで持ちこたえた。それは #2 の中身が良かったからだ。中身は、これから全部の牛に入る。#2 は、消えるんじゃなく、増える」

　高梨は少し考えて、「わかりました」と言った。岡崎の「わかりました」に近かった。

---

　赤海は AWS の画面で、Auto Scaling という設定を見せた。

```
起動テンプレート: yamabiko-web-v12
  AMI:             ami-0a1b2c3d（プログラム入りのイメージ）
  インスタンスタイプ: t3.medium
  ユーザーデータ:    起動時に S3 から設定を取得し、ウェブサーバーを開始

Auto Scaling グループ: yamabiko-web
  最小: 3   希望: 3   最大: 30
  スケーリングポリシー:
    CPU 平均が 60% を超えたら +3 台
    CPU 平均が 20% を下回ったら -1 台（最小 3 まで）
  ヘルスチェック: ALB が「生きていない」と判断した台は入れ替え
```

「これが、家畜の柵だ。今は三頭いる。CPU が六十パーセントを超えたら、同じ中身のサーバーを三頭増やす。落ち着いたら減らす。ALB が『この一頭は返事をしない』と言えば、その一頭を殺して、新しい一頭を作る。全部、人がいなくても起きる」

「殺す」

「業界用語だ。kill という」

「牛なのに」

「牛なのに、だ」

　桐山が「赤海語録」に「牛なのに、だ」と書いた。

「起動テンプレートの v12 というのは」

「テンプレートの版だ。プログラムを更新したら、新しいイメージを作って v13 にする。柵に『これからは v13 を使え』と言うと、柵は v12 の三頭を一頭ずつ v13 に入れ替える。お客さんは気づかない。高梨さんが三台に順番に入って更新する作業は、なくなる」

　そこへ三上が来た。ドアの外から声がした。

「サーバーが三十台になるって聞いたぞ！」

「なります」

「じゃあ、俺のカートも三十個になるのか」

「なりません。カートは ElastiCache に一つです」

「三つだろう」

「……三つです」

「三十台に、名前をつけていいか」

「つけないでください。番号もつけません」

「なんでだ」

「名前をつけると、殺せなくなります」

　三上は「殺す？」と言い、桐山が「業界用語です」と言い、三上は「わかった！」と言って出ていった。わかっていなかった。

　桐山がメモした。

> サーバーはペットから家畜へ。牛。
> 家畜にするには、サーバーの中に「そこにしかないもの」を置かない。
> セッション、画像、ログ、設定を外に出す。
> 起動テンプレート＋Auto Scaling で、機械が増減と入れ替えをする。
> （#2 は消えるのではなく増える。名前をつけると殺せなくなる）

## 第二章　僕の環境では動く

　四月の第一週、桐山が初めての機能を作った。

　商品ページに「この商品を買った人はこれも買っています」を出す機能だ。データは Snowflake の営業マートから毎晩取ってくる。桐山は自分のパソコンで作り、動いた。高梨がコードを見て、問題ないと言った。

　金曜の夕方、高梨がそれを本番のウェブサーバーに入れた。

　商品ページが真っ白になった。

　高梨は十分で元に戻した。お客さんへの影響は十分間だった。原因は、桐山が使ったライブラリの版だった。桐山のパソコンには最新の版が入っていて、本番のサーバーには二年前の版が入っていた。最新の版にしかない機能を、桐山は使っていた。

「僕の環境では動きました」

　桐山は言った。それは事実だった。

「言うと思った」

　赤海が言った。

「その台詞は、この業界で、たぶん一日に百万回言われてる」

「……すみません」

「謝る台詞じゃない。事実の報告だ。事実が、問題なんだ」

---

　月曜、小部屋で赤海はホワイトボードにこう書いた。

```
桐山さんのパソコン     macOS、Python 3.12、ライブラリ X の版 4.2
高梨さんのパソコン     macOS、Python 3.11、ライブラリ X の版 3.8
本番サーバー            Ubuntu、Python 3.10、ライブラリ X の版 3.1
```

「三つとも違う。桐山さんのパソコンで動いたプログラムが、本番で動く保証は、最初からなかった。二年間それで事故が起きなかったのは、高梨さんが一人で、自分のパソコンと本番を、なんとなく揃えてたからだ。二人目が来た瞬間に、それは崩れた」

「揃えます」

　桐山が言った。

「人が揃えるのは、無理だ。高梨さんですら、自分のパソコンと本番が違うことに気づいてなかった」

「気づいてなかったです」

　高梨が認めた。

「三・八と三・一、違うんですね」

「違う」

　赤海は別のことを書いた。

```
コンテナ ＝ プログラムと、それを動かすのに必要なもの全部を、一つの箱に詰めたもの
```

「Docker という道具がある。Dockerfile というファイルに、『Ubuntu を土台にして、Python 3.10 を入れて、ライブラリ X の 3.1 を入れて、ヤマビコストアのプログラムを入れる』と書く。Docker はそれを読んで、箱を一つ作る。イメージという」

```
FROM python:3.10-slim
COPY requirements.txt .
RUN pip install -r requirements.txt   # ライブラリ X == 3.1 と書いてある
COPY . /app
CMD ["gunicorn", "app:server"]
```

「この箱を、桐山さんのパソコンで動かす。高梨さんのパソコンで動かす。本番で動かす。箱の中身は全部同じだ。箱の外が macOS だろうと Ubuntu だろうと、箱の中は Python 3.10 でライブラリ X は 3.1 だ」

「僕のパソコンで動けば、本番でも動く」

「箱の中で動けば、本番でも動く。パソコンの外は関係なくなる」

　早瀬が入口から顔を出していた。

「弁当箱ですね」

「……近い」

「近いですか！」

「中身が同じなら、どこで開けても同じ弁当だ。近い」

　早瀬は「弁当箱」とメモして、「（近い）」と書いた。「（郵便局ではない）」の隣だった。

　高梨が聞いた。

「先週の Auto Scaling は、AMI というイメージを使ってました。あれとは違うんですか」

「似てるが、粒度が違う。AMI はサーバー一台丸ごとの写しで、数ギガバイトあり、作るのに十分かかる。コンテナのイメージは、プログラムと必要なものだけで、数百メガバイト、作るのに一分。そして、サーバー一台の上で、複数のコンテナを動かせる」

　赤海は絵を描いた。

```
今
  EC2 #1 ── ウェブサーバー（プログラムが直接入っている）
  EC2 #2 ── ウェブサーバー
  EC2 #3 ── ウェブサーバー

これから
  ECS（コンテナの柵）
    ├─ web コンテナ × N   （ヤマビコストア）
    ├─ api コンテナ × M   （丸嘉向け在庫 API）
    └─ batch コンテナ × 1 （夜間の「買った人はこれも」集計）
  （下にどのサーバーが何台あるかは、Fargate が面倒を見る）
```

「ECS は、コンテナ用の柵だ。先週の Auto Scaling がサーバーの柵なら、こっちはコンテナの柵。『web を三個動かせ』と言えば三個動かし、CPU が上がれば六個にする。Fargate というのは、その下にサーバーが何台要るかを AWS に任せるやり方で、ヤマビコはもう EC2 の台数を考えなくてよくなる」

「牛の柵の中に、弁当箱の柵」

　早瀬が言った。

「もう例えるな」

「はい」

「Kubernetes というのは聞いたことがあります」

　桐山が言った。

「Kubernetes は、コンテナの柵の、もう一つの流儀だ。ECS は AWS 専用で単純。Kubernetes はどのクラウドでも動くが、覚えることが十倍ある。エンジニアが二人の会社は、ECS でいい。エンジニアが二十人になって、AWS 以外も使いたくなったら、Kubernetes を考える」

「二十人」

「今は二人だ」

「二人と、赤海さん」

「俺は社員じゃない。契約書の件名は『調査』だ」

　桐山が「赤海語録」に「契約書の件名は『調査』」と書いた。赤海語録の最初のページには、すでに「誰にも頼まれてない」「調査の一環だ」が並んでいた。

「ライブラリの版が違った、という今回の事故は、コンテナで防げるんですか」

「防げる。Dockerfile に『ライブラリ X は 3.1』と書いてあれば、桐山さんが自分のパソコンに 4.2 を入れてても、箱の中は 3.1 だ。桐山さんは箱の中で開発するから、4.2 の機能を使った時点で、自分のパソコンで動かなくなる。本番に入れる前に気づく」

「『僕の環境では動く』が、言えなくなる」

「言えなくなる。箱の中が、全員の環境になる」

　桐山はメモした。

> 「僕の環境では動く」は、環境が違うという告白。一日百万回言われている。
> コンテナ＝プログラムと動かすのに必要なもの全部を箱に詰める。箱の外は関係なくなる。弁当箱（近い）。
> Dockerfile＝箱の作り方の記述。イメージ＝作られた箱。
> ECS / Kubernetes＝コンテナの柵。Fargate＝下のサーバーを AWS に任せる。

---

「一つ、聞いていいですか」

　帰り際に、桐山が赤海に言った。

「Dockerfile を書けば箱は同じになりますけど、AWS の設定は同じになりませんよね。ECS の柵の設定とか、ALB とか、セキュリティグループとか。高梨さんが画面で作ったものは、僕には見えません」

　赤海は、桐山の顔をしばらく見た。

　それから、からあげ棒を、桐山に差し出した。

「……いいんですか」

「その質問が出るのに、二週間かかると思ってた」

「え」

「食え」

　桐山は食べた。食べながら、「赤海語録」に何か書こうとして、両手が塞がっていることに気づいて、やめた。

「次の話だ。丸嘉のテスト環境を作る話がある。高梨さんの画面クリックを、全部書き起こす」

「全部」

「二年分だ」

　高梨が、隅で「二年分……」と呟いた。

## 第三章　クリックの記録

　丸嘉との連携開始は五月の連休明けと決まっていた。その前に丸嘉は「本番と同じ構成のテスト環境で、二週間の結合テストをしたい」と言ってきた。当然の要求だった。

「本番と同じ構成のテスト環境を、作れますか」

　梨乃が高梨に聞いた。高梨は答えた。

「作れます。三日ください」

　三日後、テスト環境はできた。丸嘉がテストを始めた。

　二日目に、丸嘉から連絡が来た。「テスト環境では在庫 API が三秒かかります。本番はいくつですか」。

　高梨が調べた。テスト環境の API コンテナは、本番より小さいサイズで作られていた。高梨が画面で作るときに、選択肢を一つ間違えていた。直した。

　四日目、また連絡が来た。「テスト環境の WAF が、弊社の番号を拒否します」。本番の WAF に足した丸嘉の許可規則を、テスト環境の WAF には足していなかった。

　五日目、赤海は高梨と桐山を小部屋に呼んだ。

「高梨さんが三日かけて作ったテスト環境は、本番と『だいたい同じ』だった。だいたい、が二か所見つかった。まだあるかもしれない。あるかどうかを確かめる方法が、ない」

「画面を見比べれば」

「AWS の画面で、本番とテストを一項目ずつ見比べる。VPC、サブネット、セキュリティグループ、ALB、WAF、ECS、RDS、ElastiCache、S3、CloudFront、Route 53。設定項目は、合計で千を超える。人が見比べて漏らさない自信はあるか」

　高梨は黙った。

「千個、頑張れって言えないです」

「言えない」

---

　赤海はホワイトボードに、三つの言葉を書いた。ここに集まった全員が、その三つを、前の話で見たことがあった。

```
志村さんの台帳    商品の正本ではなく、五つのシステムの写しだった
岡崎さんのExcel   人の正本ではなく、十二のサービスの写しだった
高梨さんの記憶    インフラの正本ではなく、AWS の画面の写しだった
```

「今のヤマビコの AWS は、高梨さんが二年かけて画面でクリックした結果だ。正本は高梨さんの頭の中にしかない。だからテスト環境を作るには、高梨さんが頭の中から三日かけて再現する。再現は『だいたい』にしかならない」

「僕の頭が、写しなんですか」

「頭が写しで、正本がない状態だ」

「……本当の最新、じゃないんですね」

「本当の最新でもない」

「正本を作る」

　桐山が言った。梨乃と早瀬が、同時に小さく笑った。三回目だった。

「そうだ。インフラの正本を、コードで書く。Infrastructure as Code、IaC という。Terraform という道具を使う」

「テラフォーム」

　早瀬が言った。

「テラ、フォーム……地形を、作る。つまり、造成ですね！」

　赤海が、止まった。

「……当たってる」

「え？」

「Terraform は、地形を作るという意味だ。惑星を人の住める土地に変える、という SF 用語からきてる。クラウドの何もない場所に、敷地と区画と道を作る。造成だ」

「当たりましたか」

「当たった」

　早瀬は、しばらく動かなかった。それから、ゆっくりとメモ帳を開いて、「造成（当たった）」と書いた。「（郵便局ではない）」「（近い）」の下だった。初めての、括弧なしに近い当たりだった。

　桐山が「赤海語録」に「当たってる」と書いた。赤海が言った言葉のうち、最も珍しいものだった。

　赤海は、テキストファイルを一つ開いた。

```hcl
# vpc.tf
resource "aws_vpc" "main" {
  cidr_block = "10.0.0.0/16"
  tags       = { Name = "yamabiko-${var.env}" }
}

resource "aws_subnet" "public_1a" {
  vpc_id            = aws_vpc.main.id
  cidr_block        = "10.0.1.0/24"
  availability_zone = "ap-northeast-1a"
}

resource "aws_subnet" "private_1a" {
  vpc_id            = aws_vpc.main.id
  cidr_block        = "10.0.11.0/24"
  availability_zone = "ap-northeast-1a"
}

# security.tf
resource "aws_security_group" "db" {
  vpc_id = aws_vpc.main.id
  ingress {
    from_port       = 3306
    to_port         = 3306
    protocol        = "tcp"
    security_groups = [aws_security_group.web.id]
  }
}

# ecs.tf
resource "aws_ecs_service" "api" {
  name          = "api"
  desired_count = var.env == "prod" ? 3 : 1
  launch_type   = "FARGATE"
  ...
}
```

「四つ目の話で見た敷地の絵が、そのまま文字になってる。VPC、サブネット、門番、柵。全部で二千行ほどある。俺と桐山さんで、先週、高梨さんの画面クリックを全部書き起こした」

「二千行」

「二年分の、クリックだ」

「僕、そんなにクリックしてたんですか」

「してた。三千回くらい」

「……頑張ってましたね、僕」

「頑張ってた。だから書き起こせた」

```
                    自分で建てる                借りる

倉庫システム         新しいサーバーを買う          ベンダーのクラウド版（SaaS）
データベース         MySQL を EC2 に              RDS（もう借りている）
セッション          Redis を EC2 に              ElastiCache（もう借りている）
```


「Elasticsearch を EC2 に入れると、月に一万円で済む。OpenSearch を借りると三万円。二万円の差だ。ただし、Elasticsearch には年に数回、セキュリティの修正が出る。それを追いかけて、深夜に更新して、動かなくなったら戻すのは、高梨さんか桐山さんだ。二人が忙しくて半年放置した Elasticsearch は、去年の倉庫の共用パソコンと同じものになる」

「得意でも、やめろ」

「はい」

## 付録　登場した仕組みと用語

| 物語での呼び方 | 正式名称 | 製品例 | 役割 |
|---|---|---|---|
| ペットと家畜（牛） | Pets vs Cattle | — | 名前を付けて世話する vs 番号で増減・入れ替え。社長が当てた回 |
| そこにしかないもの | 状態（ステート） | セッション、画像、ログ、設定 | サーバーの外に出す。ステートレスにする |
| 家畜の柵 | Auto Scaling グループ | AWS Auto Scaling | 起動テンプレートから増減・入れ替え。名前をつけると殺せなくなる |
| 箱（弁当箱・近い） | コンテナ / イメージ | Docker | プログラムと依存を一つに詰める。環境差をなくす |
| 箱の作り方 | Dockerfile | — | 土台・依存・プログラムを順に記述 |
| コンテナの柵 | コンテナオーケストレーション | ECS, Kubernetes | 何個動かすか、落ちたら入れ替え |
| 下のサーバーを任せる | Fargate | AWS Fargate | サーバー台数を意識しない |
| クリックの記録（造成） | IaC | Terraform, CloudFormation, Pulumi | インフラの正本をコードに。plan / apply。早瀬が当てた回 |
| ずれ | ドリフト | — | コードと実態の差。plan で必ず見える |
| 登記簿 | Terraform state | S3 + ロック | 失うと管理不能。共有・版・鍵。法務局は自分の机にない |
| 建てるか借りるか | IaaS / PaaS / SaaS | EC2 / RDS, ECS / SaaS 型 WMS | 責任の線の位置 |
| 責任の線 | 責任共有モデル | — | データの中身と権限は常に自分の責任 |
| たまに起きる短い仕事 | サーバーレス | Lambda | イベント駆動。動いていない間は存在しない。靴紐も |
| 独立した建物群 | AZ（アベイラビリティゾーン） | ap-northeast-1a/1c/1d | 一つに全部置かない。卵と籠 |
| 待機との同期 | マルチ AZ | RDS Multi-AZ | 六十秒で切り替え。実測四十八秒 |
