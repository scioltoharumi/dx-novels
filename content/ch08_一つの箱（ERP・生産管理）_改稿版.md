# 一つの箱（改稿版）

## 第一章　基幹を統合すべき

「基幹システムを、ERP に統合すべきです」

　一月、主幹事候補の証券会社の引受審査部から来た二人のうち、年上のほうがそう言った。上場準備の初回面談だった。梨乃、橘、赤海、大河内が同席していた。

　三上も、なぜかいた。「証券会社と聞いて」と本人は言った。

「御社は、会計、受注、倉庫、購買、経費、固定資産、給与が、それぞれ別の SaaS です。七つ。それを御社独自の対応表と API でつないでる。監査法人のショートレビューは通ったと聞いてますが、上場審査では、『基幹業務が一つの統制された基盤に載ってるか』を見ます。一般的には、ERP を導入して統合するのが、審査上わかりやすい」

　大河内が聞いた。

「ERP というのは、何だ」

　年下のほうが答えた。

「統合基幹業務システムです。会計、販売、購買、在庫、生産、人事を、一つのシステム、一つのデータベースで持ちます。SAP、Oracle、Microsoft Dynamics が大手で、国内なら OBIC、富士通、あと中堅向けのクラウド ERP がいくつか」

「SAP」

　三上が言った。

「強い」

「……はい？」

「名前が強い。三文字で」

　年下のほうは、答えなかった。年上のほうが、続けた。

「いくらかかる」

　大河内が聞いた。

「御社の規模——三社、売上五十億、社員百二十人——なら、中堅向けクラウド ERP で、初期五千万から一億、期間一年から一年半、というのが相場です」

　大河内は、橘と赤海を見た。二人とも、すぐには答えなかった。

「ERP ってのはな」

　社長が、証券会社の前で、例えを始めた。梨乃は止められなかった。

「……箱だ。箱は、何でも入る」

「はい」

「何でも入る箱は、何を入れたか、忘れる」

　証券会社の二人が、少し驚いた顔をした。赤海が、からあげ棒を齧るのをやめた。

　梨乃はメモに「何でも入る箱は、何を入れたか忘れる（社長）」と書いた。これが当たる半分かどうかは、この時点ではわからなかった。

---

　面談のあと、小部屋に四人が集まった。三上は帰った。

「ERP を、私は正確に説明できません」

　橘が先に言った。

「三十年前の会計ソフトからクラウド会計に移したライズを見てきましたが、ERP を触ったことはない。前職の会社は ERP を使ってましたが、私は経理で、会計モジュールの画面しか見てなかった。会計上は、それで足りてました」

　相殺後、七。年が変わっても続いていた。

　赤海が、ホワイトボードに向かった。

「俺は、前職で ERP の導入プロジェクトに二年いた。失敗した側だ。だから、説明はできる」

　桐山が「赤海語録」を開いた。赤海の前職の話は、三年で初めてだった。

　赤海は、まず年表を書いた。

```
1960 年代   MRP     工場で、製品を作るのに部品がいつ何個要るかを計算する仕組み
1980 年代   MRPII   MRP に、工場の能力と、原価と、購買を足した
1990 年代   ERP     MRPII に、会計と、販売と、人事を足した。「企業の資源を全部計画する」
2010 年代〜 クラウド ERP  同じものを、月額で借りる
```

「ERP の出発点は、工場だ。『靴を千足作るには、靴紐が二千本、いつまでに要る』を計算する道具が、会計と販売と人事を飲み込んで、会社全体になった」

「エンタープライズ・リソース・プランニング」

　早瀬が言った。

「企業の、資源を、計画する。企業の資源というのは、人と、物と、金。それを全部、計画する。つまり、全部」

「……訳しただけだが、当たってる」

「当たりましたか」

「英語の当たりが、これで四つ目だ」

「英語なら、当たります」

「郵便局は英語じゃなかった」

「郵便局は日本語でした」

　次に、赤海は箱を描いた。箱は、社長の言葉のせいで、少し大きめだった。

```
┌──────────────────────── ERP ────────────────────────┐
│                                                      │
│   販売   購買   在庫   生産   会計   人事   固定資産    │
│    │      │      │      │      │      │      │       │
│    └──────┴──────┴──────┴──────┴──────┴──────┘       │
│                          │                           │
│                   一つのデータベース                     │
│            （品目・取引先・勘定科目・社員が一つ）           │
└──────────────────────────────────────────────────────┘
```

「ERP の本質は、モジュールが七つあることではない。七つが、一つのデータベースを見てることだ。販売で受注を入れると、在庫が減り、会計に売掛金の仕訳が自動で立つ。購買で発注を入れると、検収で在庫が増え、会計に買掛金が立つ。人が『受注システムから会計へ請求データを送る連携』を作らなくていい。最初から、同じ箱の中にいる」

　梨乃が、壁の図を見た。七枚あった。

「私たちが、三年かけて作ったものは」

　赤海は、もう一つ、箱を描いた。今度は、箱は七つあった。

```
  受注 SaaS ──API──┐
  倉庫 WMS ───API──┤
  購買 SaaS ───API──┼──▶ xref（正本）◀──▶ クラウド会計 A ──▶ レイク → DWH → BI
  経費 SaaS ───API──┤          ▲
  固定資産 SaaS ─API─┤          │
  給与システム ──API─┘      Entra ID（人の正本）
```

「これが、ヤマビコグループの今だ。七つの箱を、二つの正本と API でつないでる。ERP は、これを一つの箱にする。正本は箱の中に入り、API はなくなる」

「どっちが正しいんですか」

「どっちも正しい。証券会社が言ったのは、『一つの箱のほうが、審査で説明しやすい』だ。それは事実だ。一つの箱には、統制と証跡が最初から組み込まれてる。橘さんが手で作った職務分掌と三点照合と承認ログは、ERP なら設定項目だ」

「じゃあ、一つの箱にすべきだ」

　大河内が言った。赤海は、少し間を置いた。

「社長、それを決める前に、俺が前職で見た二年間の話を、一度聞いてください」

「長いか」

「二十分です」

「志村より短いな」

「志村さんより短いです」

　梨乃はノートに書いた。

> ERP＝会計・販売・購買・在庫・生産・人事が、一つのデータベースを見る。出発点は工場の所要量計算。全部（早瀬・英語）。
> 本質はモジュールの数ではなく、一つのデータベース。取引を入れると、仕訳が自動で立つ。
> ヤマビコは、七つの箱を、二つの正本と API でつないだ。ERP は、それを一つの箱にする。
> 一つの箱には、統制と証跡が最初から入っている。証券会社が言っているのは、そのこと。
> （何でも入る箱は、何を入れたか忘れる。当たるかどうかは、まだわからない。SAP は三文字で強い）

## 第二章　箱の中と外

「前職は、売上八百億の小売チェーンだった。全社 ERP の導入に、四年と六十億かけた。俺がいたのは、後半の二年だ」

　赤海は、珍しく、長く話した。からあげ棒は、机の上に置かれたままだった。三年で初めて、赤海が食べずに話すのを、梨乃は見た。

「ERP には、『標準』がある。受注はこの画面で、この項目で、この順番で入れる。承認はこの階層で。在庫はこの単位で。世界中の何万社が、その標準で業務を回してる。ERP を入れるというのは、その標準に、自分の業務を合わせることだ。Fit to Standard という」

「Fit & Gap の、逆ですね」

　早瀬が言った。

「逆ではない。同じ思想の、強い版だ。Fit & Gap は『合うか合わないか見る』で、Fit to Standard は『合わせろ』だ」

「半分ですか」

「半分だ」

　早瀬は「Fit to Standard（半分）」と書いた。

「ERP は Gap が出たとき、二つの選択肢がある。業務を変えて標準に合わせるか、ERP を改造して業務に合わせるか。改造を、アドオンという」

　赤海は数字を書いた。

```
前職の ERP 導入
  要件定義で出た Gap        1,400 件
  業務を変えて吸収           200 件
  アドオンで対応            1,200 件   ← ここで失敗した
  アドオンの開発費          38 億円
  導入後、ERP の版が上がるたびに壊れたアドオン   毎回 100〜300 本
  結局、版を上げられなくなった
```

「千二百本のアドオンは、『今の業務を一切変えたくない』という現場の声を、全部聞いた結果だ。店舗の発注画面は今のままがいい。伝票の様式は今のまま。承認は部長の後に副部長も。全部、標準にない。全部、作った。作ったものは、ERP の版が上がると壊れる。壊れるから版を上げない。版を上げないと、保守が切れる。六十億かけて、二〇〇八年版の ERP を、二〇二〇年まで使った」

　小部屋が静かになった。桐山は、語録に「六十億」と書いて、その下に「二〇〇八年版」と書いて、ペンを止めた。

「天気は、入ったんですか」

　三上が、いつの間にか入口にいた。

「……天気？」

「受注画面に。千二百本の中に、天気はあったか」

「あった」

「あったのか！」

「天気と、大安仏滅と、店長の誕生日が出る画面があった。全部、版上げで壊れた」

「天気が」

「天気が」

　三上は、しばらく考えて、「わかった」と言った。小さい声だった。天気を諦めた瞬間だったのかもしれない。梨乃は、それを記録した。

「ERP が悪いんじゃない。ERP は、業務を標準に合わせる覚悟がある会社には、最強の道具だ。覚悟がない会社には、六十億の檻になる」

　赤海は、そこで初めて、からあげ棒を手に取った。話が終わった合図だった。

---

「ヤマビコに、覚悟はありますか」

　橘が、梨乃に聞いた。梨乃は、三年間を振り返った。

「三上さんは、FAX をウェブに変えてもらうために、会長さんの下山を待って電話しました。志村さんは、五回の登録を一回にして、手が寂しいと言いながら靴紐を結び直しました。橘さんは、三社の勘定科目を一つにしました。業務を変えることは、この会社は、たぶんできます」

「では、ERP でもいい」

「ただ、私たちは、業務を変えるたびに、それを自分たちで決めてきました。ERP は、決める前に、標準が決まってる。それに合わせられるかどうかは、標準を見てみないとわかりません」

　赤海が続けた。

「もう一つ、見ておくべきことがある。一つの箱に入れると、何を失うかだ」

```
一つの箱に入れると得るもの
  仕訳の自動生成。連携を作らなくていい
  マスタが一つ。xref が要らなくなる
  職務分掌・承認・証跡が最初から入っている
  ベンダーが一社。責任の所在が明確
  審査で説明しやすい

一つの箱に入れると失うもの
  受注 SaaS の、EC 向けの細かい機能（丸嘉 API 受信、返品の状態管理）
  倉庫 WMS の、倉庫向けの細かい機能（ハンディ端末、ロケーション管理）
  道具を一つずつ、良いものに替える自由。箱の中は、箱の版に縛られる
  xref。ただし、xref は ERP の中のマスタに置き換わるので、失うというより移る
  料金。七つの SaaS の合計は月 80 万。中堅 ERP は月 150〜250 万、プラス初期 5,000 万〜
  川辺さんと真田さん。SaaS ごとの導入担当は、ERP では一社のSI になる
```

「川辺さんを失うんですか」

　早瀬が言った。

「オーダーリンクをやめれば、川辺さんは来なくなる」

「充電器四本の人が」

「充電器四本の人が」

　森田が、廊下でそれを聞いていた。何も言わなかったが、立ち止まった。

「受注 SaaS は、Fit 率八割で選んだ。ERP の販売モジュールは、EC 向けではなく、卸売・製造向けに作られてる。丸嘉の API 受信は標準にないかもしれない。返品の状態管理は、たぶんない。それを『業務で吸収』できるか、『アドオン』になるか」

「アドオンになったら、前職と同じ道」

「本数が違う。前職は千二百本。ヤマビコで出るのは、たぶん二十本だ。二十本なら、管理できる。ただし、二十本で済むかどうかは、標準を見るまでわからない」

「天気は、入れない」

　三上が言った。自分に言い聞かせるようだった。

「入れない」

---

「一つ、聞いていいですか」

　早瀬が言った。

「証券会社は、『統合された基盤』と言いました。でも、私たちが三年でやったのは、正本を作って、つないで、証跡を残すことでした。小野さんは、それを『統制』と『証跡』と呼んで、三十九件で済んだと言った。それは、統合されてなくても、統制されてる、ということではないんですか」

　赤海は、早瀬を見た。からあげ棒が、十度。

「その通りだ。証券会社が本当に見たいのは、箱が一つかどうかではない。『取引が、承認を通って、証跡を残して、会計に正しく届くか』だ。ERP は、それを最も簡単に見せられる道具だが、唯一の道具ではない」

「じゃあ、ERP を入れなくても」

「入れなくても、審査は通せる。ただし、七つの箱と二つの正本と API を、『これで統制されてます』と文書で説明する手間がかかる。ERP なら『ERP です』で済む。その手間を、どう見るか」

　橘が言った。

「その手間は、もう半分やりました。売上計上基準の文書、権限の棚卸し、差異の記録。残りの半分は、連携の設計書と、xref の運用手順書を、審査用に整えることです」

「岡崎さんの四十二ページも」

「あれは契約書の別紙です。ただ、内容は、三分の一くらい使えます」

　赤海は頷いた。

「では、ERP を入れるかどうかは、審査のためではなく、業務のために決める。業務のために、今の七つの箱で足りてないところは、どこか」

　梨乃は、一つだけ、思い当たった。

「ライズの、工場です」

「なぜだ」

「柳さんの電卓です」

「電卓？」

「先週、長野に行ったとき、柳さんが原価を電卓で計算してました。ソーラー式の」

　赤海は、少し黙った。

「……何でも入る箱に、電卓は入るか」

「社長の例えを使わないでください」

「使った」

　梨乃はノートに書いた。

> Fit to Standard＝業務を ERP の標準に合わせる。Fit & Gap の強い版（早瀬・半分）。
> Gap をアドオンで埋めると、版が上がるたびに壊れ、版を上げられなくなる。六十億の檻。天気も壊れた。
> ERP は覚悟がある会社の最強の道具。覚悟がない会社の檻。
> 一つの箱で得るもの：自動仕訳、マスタ一つ、統制の組み込み、責任一社。失うもの：用途別の細かい機能、道具を替える自由、料金、川辺さん。
> 審査が見るのは、箱の数ではなく、統制と証跡。統合されていなくても、統制はできる。ただし説明の手間がかかる。
> ERP を入れるかは、審査のためでなく、業務のために決める。
> （赤海さんが食べずに話した二十分。部長が天気を諦めた瞬間。柳さんの電卓はソーラー式）

## 第三章　ライズの原価

　二月、梨乃と早瀬と橘は、長野に行った。

　ライズ・フットウェアの工場は、従業員三十五人、月に八千足を作る。工場長は柳という五十代の男性で、二十年、この工場を回してきた。

　柳は、話が短い。志村と熊谷の後だと、驚くほど短い。

「原価は、どうやって出してるんですか」

　橘が聞いた。

「電卓と Excel」

　柳は、六秒で答えた。それから、自分のパソコンの Excel を開いた。ファイル名は「原価計算_2030.xlsx」だった。

「2030」

「西暦」

「今、何年でしたっけ」

「知らない。ファイル名は、去年つけた」

　柳の机には、ソーラー式の電卓があった。三十年使っている、と柳は言った。六秒で。

「靴一足の原価は、材料費と、人件費と、電気代とか機械の償却とかの経費を足したもの。材料費は、この表の部品表から。トレイルシューズIII の黒の二十六センチなら」

```
部品表（BOM）　トレイルシューズIII　黒　26.0
  部品                  数量    単価      金額
  アッパー（合成皮革）    1 足分   1,240    1,240
  ミッドソール（EVA）    1 足分     680      680
  アウトソール（ラバー）  1 足分     520      520
  靴紐                  2 本       45       90
  インソール            1 足分     310      310
  接着剤                12g        8/g      96
  ロゴ・タグ・箱         1 式      180      180
  材料費 計                                3,116

  加工費（工程ごと）
  裁断      6 分 × 40 円/分     240
  縫製     18 分 × 40 円/分     720
  成型      9 分 × 55 円/分     495
  仕上げ    5 分 × 40 円/分     200
  加工費 計                    1,655

  製造原価                     4,771
```

「ボム」

　早瀬が言った。

「BOM。ビー・オー・エム。部品表。……爆弾ではなく」

「爆弾ではない」

　柳が言った。六秒。

「Bill of Materials です」

　橘が言った。早瀬は「BOM（爆弾ではない）」とメモした。「（郵便局ではない）」の系譜だった。

「この四千七百七十一円が、ヤマビコへの卸値六千円の元になってる。ただし」

　柳は、少し言いにくそうに——といっても六秒で——言った。

「この単価は、去年の四月のもの。ラバーは、その後、二割上がった。EVA も一割。私は半年に一度、単価を更新してる。それと、加工費の『四十円／分』は、工場全体の人件費を、月の総作業時間で割ったもので、これも半年に一度」

「では、今、トレイルシューズIII を一足作ると、実際にいくらかかってるかは」

「正確には、わからない。だいたい五千百円くらいだと思う」

「だいたい」

「電卓では、だいたい、までしか出ない」

　橘が、静かに聞いた。

「ヤマビコへの卸値は六千円。粗利は、去年の四月なら千二百二十九円、今なら九百円くらい。それは、社長は知ってますか」

「知らないと思う。前の社長も、聞かなかった」

「大河内も、聞かないと思います。体温しか聞かないので」

　柳は「体温？」と言い、梨乃は「あとで説明します」と言った。説明は六秒では終わらなかった。

---

　帰りの新幹線で、橘は言った。

「これが、七つの箱で足りてないところです」

　橘はノートに書いた。

```
ライズの工場に、今ないもの
  部品表（BOM）の正本       Excel。製品ごとに柳さんが手で持つ。単価は半年に一度
  所要量計算（MRP）         ヤマビコから「来月三千足」と言われたら、ラバーがいつ何キロ要るかを、柳さんが電卓で

  実際原価                  出ていない。標準原価（Excel の単価）だけ
```

## 終章　箱の中の正本、箱の外の正本

## 付録　登場した仕組みと用語

| 物語での呼び方 | 正式名称 | 製品例 | 役割 |
|---|---|---|---|
| 一つの箱 | ERP（統合基幹業務システム） | SAP S/4HANA, Oracle, Dynamics 365, NetSuite, OBIC7, GLOVIA, 国内中堅クラウド ERP | 会計・販売・購買・在庫・生産・人事が一つの DB を見る。SAP は三文字で強い |
| 出発点 | MRP → MRPII → ERP | — | 所要量計算から始まり、会社全体へ |
| 七つの箱と二つの正本 | ベスト・オブ・ブリード | 用途別 SaaS ＋ MDM ＋ API 連携 | ERP の対極。道具を選ぶ自由と、連携の設計責任。川辺さんを失わない |
| 標準に合わせる | Fit to Standard | — | 業務を製品に合わせる。「うちだけ」の八割は標準にある。Fit & Gap の強い版（早瀬・半分） |
| 改造 | アドオン / カスタマイズ | — | 版が上がると壊れる。本数が檻の高さ。天気も壊れた |
| 六十億の檻 | ERP 導入失敗の典型 | — | 業務を変えずに製品を曲げ、版を上げられなくなる。赤海さんが食べずに話した二十分 |
| 得るもの | 自動仕訳・マスタ統一・統制の組み込み・責任一社 | — | 一つの箱の価値 |
| 失うもの | 用途別機能・替える自由・料金・川辺さん | — | 一つの箱の代償 |
| 箱の数ではなく | 統制と証跡 | 説明書（構成図・マスタ・承認・連携・権限・方針・契約） | 審査が本当に見るもの。付箋も含む |
| 爆弾ではない | BOM（部品表） | — | 製品一つを作るのに要る部品と数量 |
| いつ何個要るか | MRP（所要量計算） | — | 受注 × BOM − 在庫 → 発注。納期から逆算。靴紐から始まらない |
| 工程 | 工程管理 / 作業実績 | — | 誰が、何分、何足。乾燥・再工程も工程。四十社の半分に乾燥か冷却か養生 |

| ハコデン | 生産管理システム / ERP 生産モジュール | 生産管理専業パッケージ、ERP の PP モジュール | 箱に電卓だけ入れる。証券会社には言わない（付箋が言った） |
