# 二週間分の靴（改稿版）

## 第一章　水位計

　十月十二日、日曜、午後三時。台風が関東に上陸した。

　埼玉の倉庫は、荒川の支流から八百メートルの場所にある。午後五時、市から「警戒レベル4、避難指示」が出た。ヤマビコロジ社長の佐藤は、倉庫にいた三人のパートを帰らせ、自分も六時に帰った。

　帰る前に、Slack の #helpdesk に書いた。「倉庫、避難指示。帰ります。請求書は月曜に」。西村が自動応答で「お問い合わせありがとうございます」と返した。日曜なので、それだけだった。

　午後八時、倉庫の周辺が停電した。倉庫システムのサーバーは、クラウド版に移していたので止まらなかった。だが、倉庫の中の、ハンディ端末の充電器も、ラベルプリンタも、シャッターの電動開閉も、止まった。

　午後十一時、支流の水位が、倉庫の床から二十センチ下まで来た。そこで止まった。

　月曜の朝、停電は続いていた。佐藤は倉庫に行き、水が入っていないことを確かめ、シャッターを手で開けようとして、開かなかった。電動シャッターの手動解除の方法を、誰も知らなかった。設置業者に電話がつながったのは、午前十時だった。

　月曜の出荷は、ゼロだった。EC の注文は、日曜と月曜で千二百件溜まっていた。丸嘉の注文は、百八十件。三上の注文は、二件。

　火曜の午後二時、電気が戻った。火曜の出荷は、通常の半分。水曜に、溜まった分を出し切った。

　水曜の夕方、丸嘉の担当者から、メールが来た。「今回の遅延について、貴社の事業継続計画（BCP）の有無と、内容をご教示ください」。

　三上からも、Slack が来た。「俺のテント、いつ届く」。西村が手動で「木曜です」と返した。

---

　木曜、小部屋に、梨乃、赤海、佐藤、橘、早瀬が集まった。串の缶は九つになっていて、佐藤が座る場所がなかった。佐藤は立った。

「水は、入ってない」

　佐藤が言った。

「二十センチ下で止まった。入ってたら、在庫が七億八千万、全部だめになってた。それと、今回、私が一番困ったのは、シャッターだ。手動で開ける方法を、誰も知らなかった」

「知ってる人は」

「設置業者だけ。月曜の十時まで、電話がつながらなかった」

「業者の電話番号は」

「シャッターの横に貼ってあった。付箋で」

「付箋」

「付箋です。yamabiko123 の隣に。剥がした跡の隣に」

　赤海は、ホワイトボードに向かった。

「大阪に DR を作った。東京のクラウドが止まったら、一時間で大阪に切り替える。今回、クラウドは止まってない。Snowflake も受注 SaaS も倉庫システムも、全部動いてた。動いてて、靴が一足も出なかった」

```
DR（災害復旧）    システムが止まったら、システムをどう戻すか
BCP（事業継続）   何が止まっても、事業をどう続けるか
```

「DR は、BCP の一部だ。システムは、事業の一部だから。俺たちは三年間、システムの話ばかりしてきて、去年、DR を作った。だが、倉庫が停電して、シャッターが開かなかったら、DR は何の役にも立たない」

「BCP は、誰が作るんですか」

　佐藤が聞いた。

「システムの人ではない。事業の人だ。佐藤さんと、三上さんと、志村さんと、柳さんと、橘さんと、社長。俺と高梨さんは、そのうちのシステムの部分を担当する」

「私は、ロジの社長なので、判断する権限があります」

「ある」

「では、判断します。シャッターの手動解除の手順を、シャッターの横に貼ります。付箋ではなく、プレートで」

「それが、BCP の一行目だ」

　梨乃が言った。

「私が、まとめます。受注システムのときと同じ形で」

「同じ形でいい。ただ、一つ違う。受注システムは、作れば終わった。BCP は、作ったあと、使わないことを祈りながら、毎年、訓練する」

「祈る」

　早瀬が言った。

「赤海さんが祈るんですか」

「祈らない。訓練する」

---

　その日の夕方、廊下で社長に捕まった。

「倉庫の件、どうなってる」

「BCP を作ります。丸嘉にも聞かれました」

「BCP ってのはな」

　梨乃は待った。

「……保険だ。保険は、使わないと損した気になる」

「はい」

「使うと、もっと損してる」

　社長は歩いていった。梨乃は「保険（社長）」と書いた。当たっているのかどうか、その時点ではわからなかった。当たっていることが、十か月後にわかった。

　梨乃はノートに書いた。

> DR はシステムを戻す話。BCP は事業を続ける話。DR は BCP の一部。
> システムが全部動いていて、靴が一足も出なかった。止まるのは、システムだけではない。
> シャッターの手動解除を、誰も知らなかった。業者の番号は付箋だった。BCP の最初の一歩は、そういうこと。
> BCP を作るのは、事業の人。システムの人は、その一部。
> （佐藤社長の最初の判断は、プレート。保険は使うともっと損している）

## 第二章　止まったら困る順

「最後の行は、消します」

「消してください」

　早瀬が書いた行だった。早瀬は少し残念そうに消した。

「一番右の列が、最大許容停止時間。これを超えると、取り返しがつかなくなる時間。丸嘉 API は一日。丸嘉は、API が止まると、翌日には手動発注に切り替え、三日で発注を止める、と担当者が言った」

「マキシマム・トレラブル・ピリオド・オブ・ディスラプション」

　早瀬が言った。

「最大、許容できる、中断の、期間。……そのままですね」

「そのままだ。英語、六つ目」

「六つ目です」

「もう、英語は当たりに数えない」

「数えます」

　橘が、給与の行を指した。

「給与は、二十五日に払う。二十二日までに振込データを銀行に出す。二十二日に本社が使えなければ、二十五日に払えない。それは、法令違反で、社員の生活の問題だ。売上より重い。会計上も、人としても」

　相殺後、十九。

「では、給与は、最大許容停止時間が『支払日の三日前』で、業務としては月に一回しか動かないが、その一回は絶対に止められない」

　赤海が言った。

「RTO と RPO を、システムごとに決めた。今度は、業務ごとに決める。システムの RTO は、業務の RTO から逆算する」

```

  6. 法人の受注                1 週間

```

「この八つが、BCP で守る業務だ。経費精算と新商品登録は、一か月止まっても取り返せる。守らない、のではなく、後回しにする」

「部長のテントは」

「対象外だ。部長は、止まっても、小部屋に来るだけだ」

「小部屋に来るのは、業務への影響では」

「……影響だが、許容範囲だ」

「業務影響度分析、というやつですね」

　早瀬が言った。

「BIA だ。BCP の最初の作業で、一番大事な作業だ。これをやらずに『地震が来たらどうする』から始めると、全部を守ろうとして、何も守れなくなる」

「ビジネス・インパクト・アナリシス」

「七つ目は、数えない」

「数えました」

「それと、もう一つ、見ておくことがある」

　赤海は、八つの業務の、それぞれに、何が必要かを書き足した。

```

「この表で、『一つしかないもの』を探す。埼玉倉庫は、一つしかない。長野工場は、一つしかない。倉庫の八名も、工場の三十五名も、そこにしかいない。部品屋六社のうち、ラバーは一社しか買ってない」

「一つしかないものが、止まったら」

「代わりがない。AZ を一つから二つにした。同じことを、倉庫と、工場と、部品屋で、考える。四つ目の話だ」

## 第三章　何が起きるか

　十月の第四週、梨乃は、「何が起きるか」の一覧を作ろうとして、止まった。

「地震、水害、台風、火災、停電、通信障害、感染症、サイバー攻撃、取引先の倒産、キーマンの不在、クラウドの障害。全部に、対策を書くと、十一通りになります」

　赤海は、首を振った。

「原因で分けるな。結果で分けろ」

　赤海はホワイトボードに、四つを書いた。

```
何が原因でも、起きることは四つのどれか（または組み合わせ）
  1. 場所が使えない     本社、倉庫、工場のどれかに入れない。または、そこが壊れた
  2. 人がいない         出社できない。連絡がつかない。特定の人が、いない
  3. システムが使えない  クラウドが止まった。ネットワークが切れた。暗号化された
  4. 取引先が止まった    部品屋、運送会社、社C、AWS のどれかが止まった
```

「台風で倉庫が停電したのは、一番だ。首都直下地震なら、一と二と三が同時に来る。ランサムウェアなら、三だ。部品屋が被災すれば、四だ。赤海がインフルエンザで一週間寝込めば、二だ。感染症の流行は、二と、場合によっては四」

「四つ」

　三上が、入口にいた。

「四つの札の次は、四つの使えない、か」

「そうです」

「この会社は、三つか四つだな」

「……はい」

「五つは」

「ありません」

「天気は」

「天気は、原因のほうです。台風は天気です」

　三上が、止まった。

「天気が、原因」

「はい。台風、大雪、水害。全部、天気が原因です」

「じゃあ、天気は、BCP に入るのか」

「入ります。発動基準に、気象警報が入ります」

　三上は、しばらく黙っていた。それから、言った。

「……三年、待った」

「受注画面ではありません」

「わかってる。でも、入った」

　三上は、初めて、天気について、満足した顔をした。梨乃は、それを議事録に書いた。「天気、BCP に入る（部長、三年）」。

「対策は、四通りでいい」

「四通りの対策を、八つの重要業務それぞれに書く。原因は、対策を選ぶときの参考にするだけだ」

「起きやすさと、大きさを見るためだ。それで、どこに金をかけるかを決める」

```
リスク評価
  原因                    起きやすさ    影響の大きさ    備考
  首都直下地震            低（30 年で 70%と言われるが、年では 2〜3%）   極大   本社・倉庫が同時に

「最後の行」

「消します」

「起きやすさが高くて、影響が大きいものが、優先だ。水害、ランサムウェア、赤海の不在、長野の地震。首都直下は、影響が極大だが、対策は水害とほぼ同じで、規模が大きいだけだ」

「『赤海の長期不在』が、リスク一覧に、赤海さん自身の字で書いてある」

「対策は」

「二つ。一つは、早瀬さんと桐山さんに、来年一年で、俺の仕事の半分を引き継ぐ。もう一つは、俺がいない状態で、訓練をする。六つ目の話だ」

「赤海さんがいない訓練」

「いない訓練だ」

「からあげ棒は」

「持って帰る」

「サイバー攻撃は、他と少し違う」

　赤海は、ランサムウェアの行に、印をつけた。

「地震や水害は、来たことがわかる。ランサムウェアは、来たことがわかるのは、暗号化が終わったあとだ。そして、地震は一度で終わるが、ランサムウェアは、直したあとも、まだ中にいるかもしれない」

```

  1. 感染が疑われる端末を、ネットワークから外す。全部。判断は当番、30 分以内
  2. 対策本部を立てる
  3. 支払わない。方針として、事前に社長が決めておく
  4. 警察と IPA に届け出る。サイバー保険に連絡する
  5. 個人情報が持ち出された可能性があれば、個人情報保護委員会と、本人に通知する。期限がある
  6. バックアップから戻す。ただし、バックアップが感染していないことを確かめてから
  7. 全端末を初期化する。Intune で遠隔で
```

「値切りもしない」

「値切り」

「それは、正しいです」

「当たってます」

「五番の期限は、法律で決まってる。概ね数日以内に速報、三十日以内に確報。これは、第一報と同じ形式で、宛先が違う」

「西村さんが書きますか」

「西村さんが書く。『お問い合わせありがとうございます』から始めないように」

　西村が、入口にいた。

## 第七章　長野

## 付録　登場した仕組みと用語

| 物語での呼び方 | 正式名称 | 役割 |
|---|---|---|
| システムを戻す・事業を続ける | DR（災害復旧）と BCP（事業継続計画） | DR は BCP の一行 |
| 止まったら困る順 | 事業影響度分析（BIA） | 業務ごとの影響を時間で評価し、重要業務を絞る。英語七つ目（数えない） |
| 取り返しがつかなくなる時間 | 最大許容停止時間（MTPD） | 業務ごと。丸嘉 API は 1 日、給与は支払日の 3 日前。部長のテントは対象外 |
| 業務の RTO / RPO | 目標復旧時間・目標復旧時点（業務レベル） | システムの RTO はここから逆算 |
| 一つしかないもの | 単一障害点（SPOF、業務版） | 倉庫、工場、一社購買、キーマン。赤海さんも |
| 四つの「使えない」 | 結果事象ベースのリスク分類 | 場所・人・システム・取引先。原因で分けない。天気は原因のほう |
| 起きやすさ×大きさ | リスクアセスメント | 金をかける順を決める。部長の不在は消した |
| キーマンリスク | 属人化リスク | 本人が自分で書く。引き継ぎと、いない訓練。からあげ棒は持って帰る |
| 分散・代替・在庫・外部 | 事業継続戦略（BCS） | 継続戦略の四つの型。また四つ |
| 大阪の倉庫 | 代替拠点 / 3PL | 分散。在庫の二重化と現金のトレードオフ。靴紐も寝る |
| 二社目のラバー | 複数購買（デュアルソース） | 単価 3% と引き換えの、止まらない保険。匂いが少し違う（問題ではない） |
| 二週間分の靴 | 安全在庫（BCP 目的） | 製造停止を吸収する緩衝 |
| 紙の出荷手順 | 代替手段（アナログ手順） | システムなしで一日 300 件。二人で読み合わせ。部長の住所も |
| 発電機とプレート | 設備の冗長化と手順の可視化 | 最も安く、最も効く。付箋は剥がれる |
| 消せないバックアップ | イミュータブルバックアップ（S3 Object Lock 等） | ランサムウェアが消せない。三年前の一円未満 |
| 売上ゼロで三か月 | 資金の BCP / 災害時資金繰り | 当座貸越枠、サブ口座、固定費 3 か月。それ以上は会計上、祈り |
| 払わない、値切りもしない | ランサムウェア対応方針 | 事前決定。届出（警察・IPA）、通知（個人情報保護委員会・本人）の期限。西村さんは「たぶん」 |
| 発動基準 | BCP 発動基準 | 数字で。気象警報を含む。基準未達時の判断手順も |
| 社員証の裏 | 初動カード | 安否報告、出社しない、指示を待つ、連絡先。岡崎さんが三年前から入れたかった |
| 対策本部 | 緊急時対策本部（体制・代行順） | 本部長は手を動かさない。代行順で空白をなくす。三十七ページ。集合場所に三上宅 |
| 最初の一時間 | 初動対応 | 人、止まっている業務、発動する戦略 |
| 相手の許容時間で | 対外連絡計画 | 丸嘉は 1 時間、法人は半日、全取引先は 3 日。会長は下山を待つ |
| 机の上で | 机上訓練（テーブルトップ） | シナリオ、時系列、キーマン不在設定。「連絡がつかない」設定の部長が電話に出た |
| 実際に切り替える | 実動訓練 | 大阪 DR、紙の出荷。目標と実績と差の理由。TTL を下げ忘れた |
| 直して、また訓練 | BCM（事業継続マネジメント）、ISO 22301 | 年次の見直しサイクル。印影の確認 |
| 六番まで | 取引先への BCP 開示 | 訓練結果と課題まで書いてあるかで、本物かどうかがわかる。三上宅も珍しい |
| 保険 | （社長の例え・初の外れ） | 使うともっと損している、は外れた。二十三万で済んだ |
| 十二張 | （三年間の不明の解消） | タープ四張。月一で点検。保険と同じ。今日、十三張目 |
